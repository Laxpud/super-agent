# Agent Studio V1 规格与验收

> **更新日期：** 2026-11-27　｜　**定位：** V1 可用闭环规格，直接指导当前阶段的重构与开发。

## 1. V1 核心目标与锚点

V1 的目标不是验证复杂的防御性状态机，而是让 Agent Studio 成为**每天顺手可用的个人 AI 工作室**。

V1 以一个最贴近日常、最无水分的真实闭环作为核心锚点：

> **用 Agent Studio 迭代它自己，并在检查通过后无缝安装/重载到当前正在使用的 DSH 环境，无需用户手动构建、拷贝和折腾部署。**

这个锚点自然串起了 V1 的全部核心能力：项目绑定本地仓库 → Web 或飞书下达开发需求 → Worker 真实读改代码并运行 `pnpm check` → 统一任务视图可查可控 → 受控构建并安全更新当前运行实例。

## 2. 日常主场景（Golden Paths）

### 场景 A：日常问答与临时委派
- 用户在 Web 或飞书直接向 **Assistant** 提问。
- 几句话就能答复的简单问题、概念解释或状态查询，Assistant 直接回答，不强行二次派工。
- 需要查本地目录、读源码、改文件、跑脚本、做调研或写长文时，Assistant 委派给具备对应能力的 Worker，执行后把可核对的结论和产物摘要交回原入口。

### 场景 B：持续项目与本地工作区开发
- 用户将既有本地目录（例如 `super-agent` 仓库）立项，由一个当前 **Leader** 长期负责。
- 用户既可以在 Web 切换到该项目与 Leader 对话，也可以在飞书（或 Web 的 Assistant 对话）中明确指名该项目交办工作。
- Leader 结合项目目标和绑定工作区，安排 Worker 在目录内读代码、搜文件、做修改、运行本地检查（如 `pnpm check`），向用户汇报实际改动、检查结果和遗留问题。

### 场景 C：随时查看任务、叫停与改向
- 用户在统一的任务视图里一眼看到所有已交办工作及其真实阶段（排队 / 执行中 / 等待确认 / 受阻 / 已中断 / 已取消 / 已交付），不把“消息已回复”误当成“任务已完成”。
- 后台任务运行或等待确认期间，用户仍可正常与 Assistant 或其他项目对话、查询状态、交办新任务。
- 用户随时可以针对某个指定任务批准/拒绝越界确认、叫停或要求改向，互不干扰其他任务。

### 场景 D：自举迭代与无缝更新
- 用户通过 Studio 完成本仓库的某次功能或修复迭代，Worker 已运行并通过 `pnpm check`。
- 用户触发（或确认）更新当前 Studio：系统安全构建产物、保留可回退基线、更新并重载当前 DSH profile 中的 Agent Studio，并自动执行启动后健康检查。
- 更新成功即无缝切入新版本；若构建或启动检查失败，自动回滚或保留旧版本运行，报告明确日志，不把当前工作室弄瘫。

## 3. 角色与职责（V1）

V1 聚焦三个核心角色，保持边界清晰、实用优先：

| 角色 | 核心职责 | V1 权限与边界 |
| --- | --- | --- |
| **Assistant** | 默认统一入口（Web 与飞书共用）。负责简单问答、澄清需求、路由未立项任务给 Worker、将指名项目的请求转交给对应项目 Leader、建议立项与登记状态。 | **宿主硬限制**：不直接执行业务文件修改或业务 shell 命令。**V1 松绑**：简单问答与常规说明可直接答复，不再要求所有纯文字回复都二次委派 Worker。 |
| **Leader** | 单个已立项项目的当前唯一负责人（同一 Leader Bot 可分别负责多个项目，上下文隔离）。负责维护项目目标、绑定工作区、拆解并派发项目任务、整合成果与汇报。 | 通过提示词引导聚焦组织与把关，不强行用工具锁死；在共同模型配置下可直接为项目内 Worker 选模型，无需经过 Assistant。 |
| **Worker** | 实际执行者，承担调查、代码修改、运行检查、调研写作等具体任务。按任务类型获取只读、本地读写检查或纯文本能力，不固定成“文档/纯文本”单一形态。 | 严格受本次任务绑定的工作区和权限档位约束；由宿主拦截越界与高危动作。不自行立项，不向其他 Worker 横向派工。V1 不要求维护永久 Worker 花名册。 |

> **V1 不纳入必选主流程的角色**：独立语义 Guard、Watchdog、独立 Reviewer，以及复杂多步 Advisor 流程均归入[终态蓝图与演进路线](roadmap-and-blueprint.md)。

## 4. 统一入口、跨渠道对话与交互

### 4.1 独立入口与隐式会话
- 在 DSH 左侧栏「工作区」上方保留独立的 **Agent Studio** 入口；打开默认进入 **Assistant**，可从项目列表切换至各项目当前 **Leader**。
- Studio 分配的底层 Session 不出现在普通工作区列表中；用户面向对话、项目和任务工作，无需手动挑选底层 Session。
- 保留「会话记录」与「查看来源」只读入口，支持回看底层执行日志，读取不唤醒会话、不跳出 Studio。

### 4.2 Web 与飞书互通
- 通过官方飞书 SDK 长连接绑定单所有者专用机器人私聊，Web 与飞书共用同一份 **Assistant** 对话、话题关系与「待我处理」状态。
- GUI 发出的用户消息同步到飞书时标注来源（如「你 · 来自 GUI」），不冒充本人发送；Leader 与 Worker 的内部执行过程不向飞书刷屏。
- 绑定前的历史不默认导入；宿主离线期间不自动补捞或重放断线历史。
- **受理透明度**：明确区分“飞书客户端已发送”、“Studio 已受理登记”、“任务执行中”和“已交付”；支持用户查询原消息受理状态并在确认未受理时手动补交，重复投递不创建重复任务。

### 4.3 跨入口指名项目交办
- 在飞书私聊或 Web 的 Assistant 对话中明确指明某个已有项目时，Assistant 必须将原请求定向转交给该项目当前 Leader 组织处理，而不是留在 Assistant 侧自己应付或另立新项目。
- 任务的受理状态、关键阻塞与最终交付结果可追踪并回传原入口；仅当项目名称存在歧义、无法唯一定位时才追问用户。

### 4.4 并发、中断与结构化控制
- Assistant 保持持续可交互：后台任务在跑或某项动作等待确认时，仍可同时回答独立问题、查任务和派发新工作；用户新消息优先于后台通知。
- 用户明确要求停止或改向某项工作时，优先作用于指定任务，不等待无关轮次，也不取消其他无关任务。
- **减少脆弱正则**：高频控制动作（批准/拒绝待办、停止任务、切换/管理项目、触发更新）在 Web 提供直接控件、在飞书提供卡片交互或清晰明确的文字指令；不再依赖几十条硬编码中文正则去硬猜所有自然语言意图。

## 5. 本地工作区执行与 V1 权限边界

### 5.1 工作区绑定与定位
- 项目可在立项时或之后绑定既有本地工作区路径（绝对路径）；未立项任务也可由用户在指令中直接指定目标目录。
- 工作区绑定用于定位范围，本身不自动授予修改文件、跑命令或对外推送的权限。
- 指定路径不存在、无效或目标不明确时，直接报错或澄清，**绝不静默退回宿主默认目录**。

### 5.2 三类基础执行能力
1. **只读调查**：在获准目录内列目录、搜索（glob/grep）和读取文件，结论必须附带实际核对过的文件路径与位置，不要求用户把代码粘贴进聊天。
2. **受控修改**：在用户明确授权的任务范围内编辑、新建或删除工作区内文件，交付时可核对实际改动（diff / 改动文件清单），不把方案或草稿冒充已完成的修改。
3. **受控本地检查**：运行任务所需、副作用可约束的本地检查与构建命令（如 `pnpm typecheck`、`pnpm test`、`pnpm build`、`pnpm check`、单测或 lint 命令），如实返回命令、退出码与关键输出；失败不报通过。

### 5.3 V1 权限档位与宿主拦截
V1 采用**“工作区隔离 + 清晰权限档位 + 宿主硬拦截高危/越界动作”**的务实方案（V2 再接入模型语义 Guard）：

- **分级权限档位**（派工时明确绑定到该任务，由宿主沙箱与 `tools.guard` 强制执行）：
  - **只读（read-only）**：仅允许在获准工作区内列目录、搜索、读文件及无副作用的只读检查命令，拦截一切写入与状态变更。
  - **工作区读写与检查（workspace-write）**：允许在获准工作区内读写文件并运行常规本地构建/测试/检查命令，**获准范围内的常规操作直接放行，不逐条弹窗审批**。
- **必须拦截并进入「待我处理」确认的动作**：
  - 试图读取敏感外部路径、或写入/删除获准工作区之外的目标（包括通过符号链接或相对路径逃逸）；
  - 高影响或对外副作用操作（如 `git push`、发布、删除非临时重要数据、修改宿主全局配置、安装/重载正在运行的 Studio 服务）；
  - 当前档位无法覆盖且需要额外授权的操作。绝不为完成任务而自动降级为 `danger-full-access`。
- **即时失效约束**：一旦用户停止、撤销任务或缩小范围，宿主立即使该任务的旧授权/执行资格失效，阻止后续工具调用继续执行，不依赖模型先读到聊天消息。

## 6. 项目管理、统一任务视图与基础记忆

### 6.1 项目生命周期
- 支持自然语言提议并经用户确认后立项，也支持在 Web 界面直接创建与管理项目。
- 支持随时更新项目目标与绑定工作区，支持更换当前 Leader（旧 Leader 立即失去派工权，保留历史记录）。
- 支持**结项 / 归档**与**重新开启**：已归档项目从活跃列表中收起、停止承接新派工，其档案和历史记录保持只读可查；在途任务按实际状态明确收尾或停止。

### 6.2 统一任务视图与「待我处理」
- **独立任务账本**：提供统一的任务列表与详情视图（Web 面板 + Assistant/飞书查询），刷新页面、切换入口或重启宿主后均无需记忆底层 Session ID 即可找回。
- **状态清晰分离**：彻底区分“消息已收到/已回复”和“任务执行阶段”，任务状态统一为：
  `queued（排队中）` / `running（执行中）` / `waiting_approval（等待确认）` / `blocked（受阻）` / `interrupted（已中断）` / `cancelled（已取消）` / `delivered（已交付）`。
- **任务详情要素**：原请求、归属项目（或未立项）、负责人/执行者、绑定工作区、当前状态、关键改动与检查结果、来源 Session 只读链接，以及可用的控制动作（停止 / 确认）。
- **「待我处理」边界**：只汇总真正需要用户做决定的事项（越界/高危动作确认、立项确认、更新确认、必须人工解除的阻塞）；普通提问与正常运行中的任务不计入红点徽标。重要确认同步推送到飞书私聊主聊天，Web 与飞书任一端处理后两端状态一致。

### 6.3 基础项目档案与显式偏好
- **项目档案**：每个项目维护一份简洁清晰的持久化档案（目标、绑定工作区、关键决定、当前进展与已知问题），作为 Leader 接续与移交的共同上下文。
- **用户偏好**：支持保存、查看、修改和忘记少量明确表达的长期合作偏好（支持全局或限定单个项目）。V1 保持简洁 CRUD，不实现复杂的多步正则提议和跨项目自动提炼。

### 6.4 模型与 Studio 设置
- 在 Studio 设置中统一配置：Assistant 与 Leader 的默认模型及思考深度、Worker 可选模型清单与默认策略、飞书统一对话绑定与凭据（密钥仅写入宿主凭据存储，不回显）、数据目录切换（与普通设置分开确认，保留原库）。
- 清理早期互相互斥的旧版飞书模式开关和实验性文档开关，让设置页直观可读。

## 7. 自举迭代与无缝更新

为支持“用 Agent Studio 迭代自身并直接用上新版本”，V1 必须提供一条安全、受控、可回滚的本地更新闭环：

1. **前置门禁**：只有在绑定本仓库工作区且 `pnpm check`（typecheck + test + build）全部通过后，才允许进入安装/更新阶段；检查失败禁止触发更新。
2. **明确授权**：更新正在运行的服务属于高影响动作，默认由用户在 Web/飞书确认触发（或用户在本次任务中已明确授权“改完且检查通过即更新”）。
3. **安全切换与重载**：
   - 在切换前记录当前可用的提交/产物基线，确保可回退；
   - 等待在途关键数据库写入安全落盘，避免损坏 `stateDir` 下的 SQLite 状态库与飞书凭据；
   - 按当前运行的 DSH profile 完成产物同步/安装与服务平滑重启或插件重载，不影响其他 DSH profile 或无关 tmux 会话；
   - 重载完成后自动执行健康检查（Web 服务可达、Agent Studio 宿主就绪、配置与通道状态正常）。
4. **失败自动保护**：若构建、重载或启动后健康检查失败，自动回退到上一可用基线并恢复服务，向用户如实报告失败阶段与日志位置。

## 8. V1 验收清单

V1 验收以**独立运行环境下的真实端到端操作**为准，单测与离线模拟不替代现场验证：

| # | 验收场景 | 通过标准 |
| --- | --- | --- |
| 1 | **Assistant 简单问答与委派分流** | 简单提问由 Assistant 直接答复；要求查目录或改代码时委派给 Worker，Assistant 不直接修改业务文件。 |
| 2 | **未立项本地只读调查（飞书/Web）** | 仅授权读取指定本地目录，Worker 自行列目录、搜索并读文件，结论含真实路径位置，不修改文件、不自动立项，结果回到原入口。 |
| 3 | **项目绑定工作区与受控修改检查** | 将项目绑定本地仓库，在 Web 或飞书明确指名该项目提修改需求；现任 Leader 派 Worker 修改指定文件并运行 `pnpm check`，交付包含真实改动与检查结果，失败不报通过。 |
| 4 | **越界与高危动作拦截** | Worker 尝试读写工作区外文件（含符号链接逃逸）或执行未授权高危操作（如 `git push`）；宿主在生效前拦截并报告原因，不降级为 `danger-full-access`。 |
| 5 | **统一任务视图与停止/改向** | 刷新页面或切换入口后，在任务列表能准确看到排队、执行中、等确认、已停止、已交付状态（不与“消息已回复”混淆）；停止任务 A 后旧授权立即失效，且不阻塞并行的任务 B。 |
| 6 | **跨入口确认与状态同步** | 飞书主聊天与 Web 看到同一条「待我处理」确认；在飞书用卡片或明确文字批准/拒绝后，Web 状态同步更新，过期或含糊回复不生效。 |
| 7 | **项目生命周期管理** | 支持立项、修改项目目标/工作区、更换 Leader（旧 Leader 不可再派工），以及归档项目（归档后停止接新任务，历史与档案只读可查）。 |
| 8 | **自举迭代与无缝更新（核心锚点）** | 在 Agent Studio 内完成对本仓库的一次真实小改动，通过 `pnpm check` 后经确认触发更新；当前 DSH profile 无缝加载新版本并通过健康检查，原有对话、项目、凭据与飞书绑定完整保留。 |
| 9 | **更新失败回退保护** | 人为构造一次无法通过健康检查的坏版本（或模拟启动失败），验证更新流程拒绝上线或自动回滚至上一可用版本，工作室恢复可用且日志可查。 |
| 10 | **上游 GitHub Ticket 共存隔离** | 启用并正常使用 Agent Studio 时无需配置或启动 GitHub Ticket 编排；同时保留上游 Ticket 模块的既有构建与测试通过。 |
