## 命名与统一入口

- 本项目的显示名称统一为 **Agent Studio**，包、插件、预设和项目提供的数据目录使用 `agent-studio` 命名，与上游原型区分。不改用户自定的 DSH 配置档、Git 检出目录或远端仓库名。在 DSH 左侧栏的「工作区」栏上方设置独立的统一入口，不把 Agent Studio 做成一个普通工作区。
- 打开 Agent Studio 后默认进入 Assistant 对话；也可以进入项目，直接与当前 Leader 对话。在 Studio 设置中可以查看并配置 Studio 自身的全部已支持项。DSH 的全局模型提供方、启动参数和飞书开放平台的应用权限不是 Studio 设置。
- Studio 的项目和会话不列在 DSH 左侧栏的「工作区」栏里，避免大量底层 Session 挤占普通工作区列表。这是界面展示边界，不要求拆分 DSH 的底层存储或内部索引。

## 隐式 Session

用户平时打开的是与 Assistant 或项目 Leader 的对话，而不是某个具体的 DSH Session，也不需要手动选择底层 Session。同一条对话或话题可以关联多个真实 Session；底层 Session 切换时，用户仍可在原处接续对话。同一个 Leader Bot 负责多个项目时，各项目的对话和上下文仍然分开。

真实 Session 的内容应当可查。用户可以在 Studio 的「会话记录」中查找具体 Session，也可以从消息或成果的「查看来源」进入对应记录。回看记录不会启动或继续该 Session 的工作，不跳回普通工作区。

## Assistant 的跨渠道对话

GUI 与已绑定的飞书机器人私聊是同一份 Assistant 对话的两个入口。用户从任一端发送的消息以及 Assistant 的回复，在两端都可查看并接续。同步的是用户与 Assistant 之间可见的消息、回复和话题，不包括 Leader、Worker 的内部对话和执行日志。

- 首版从绑定后开始同步文字消息及其回复和话题关系。在 GUI 发出的用户消息由机器人同步到飞书，标注「你 · 来自 GUI」，不冒充用户在飞书客户端亲自发出的消息。飞书发来的消息在 GUI 保留来源和话题归属。
- 不默认导入或批量重发绑定前的对话。若另行补录，旧消息只作为历史，不作为新指令执行。

### 引用、回复与话题

- **引用：**GUI 中每条可见消息都可以引用。引用在新消息中带上原文片段，可跳到原消息，不自动创建话题。
- **回复：**GUI 中每条可见消息都可以回复。围绕一条消息的讨论归入同一个话题，主时间线保留原消息和回复入口，不平铺话题内的所有回复。
- **接续：**从 GUI 开始的话题可以在飞书继续，反过来也一样。回复明确指向原任务时，接续原任务，不因换入口而新建一项。

### 并发与中断

- Assistant／Router 是持续可交互的统一入口。即使上一轮仍在处理、Worker 在后台执行，或某个动作在等用户确认，独立的新问题、状态查询和任务也可以得到处理，不只是收到后排队。用户消息优先于后台通知；不因用户另问一件事就取消原任务。
- 任务登记并派发后，无须等 Worker 返回结果才结束当前对话轮次。结果按实际归属回到原请求或话题；同一份可见对话不要求多个任务共用一个底层 Session。
- 用户明确更正或改向时，可以介入对应的当前轮次或已有任务；必要时中断旧推理，不将旧方向的输出当作当前答复。停止、撤销和缩小授权优先作用于指明的任务，按[更正、撤销与暂停](interaction-and-delivery.md#更正撤销与暂停)登记与报告，不等待无关轮次，也不影响其他任务。

## 待我处理

- 普通查询直接回答；需要澄清时用普通对话追问，不生成阻塞式确认。将确实需要用户决定的事项和必须由用户解除的阻塞汇总到「待我处理」，可定位原项目或任务。侧栏不为每次会话活动提示。
- 只有重要且确实缺少用户决定时才请求确认。例如，Guard 核对后发现任务需要当前未授予、但规则允许用户补充的权限。确认只暂停关联动作，不能绕过[动作授权与执行约束](action-authorization.md#代用户进行动作授权)。
- 重要事项在已绑定的飞书私聊**主聊天**中可见，不只发到话题里；说明对应工作、具体动作、范围和在等什么。GUI 与飞书使用同一事项和状态；一端处理后，另一端也能看到结果。
- 用户在 GUI 或飞书均可通过文字查询事项、明确批准或拒绝，并查看处理状态；不必须点按钮、打开网页或记固定命令。可以用任务及动作明确指认事项，或回复具体确认消息表达决定。文字和按钮使用同样的校验：必须由用户明确决定且能唯一定位仍有效的具体事项。未指明对象的「好」、含糊的选择和过期答复不生效；如果无法唯一定位，先在对话里澄清。已记录批准不等于动作已执行。
- 手机处理依赖 Studio 服务仍在运行且能连接飞书，不要求 GUI 保持打开，也不要求将 DSH 网页暴露到公网。宿主关机、休眠或断网时不能实时处理；飞书显示消息已发送，不等于 Studio 已收到或执行。

## 设置范围与生效

- 在 Studio 设置里配置 Assistant 和 Leader 的默认模型；Worker 按派工模型设置选择。对话窗口不提供临时模型切换。其他设置包括 Worker 组合及角色范围、Advisor、飞书收件、文档和记忆、监督与作业、宿主初始值和目录。
- 飞书设置可在 GUI 发现绑定入口、验证专用机器人私聊、配置密钥和解除绑定。密钥只写入宿主凭据服务，不回显；配置生效、连接在线和具体消息送达分别显示。
- 数据目录与普通设置分开确认；用户选择复制现有数据库或启用空目录，原数据保留。若配置更新有冲突、被覆盖、无法重载或结果不确定，说明实际状态，不自动重复写入。
