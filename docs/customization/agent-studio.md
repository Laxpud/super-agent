# 使用 Agent Studio

Agent Studio 是 DSH Web 左侧独立入口，不是普通工作区。打开后默认进入 **Assistant**，可从项目列表切到当前 **Leader**。Assistant 和各个项目分别保存对话；同一个 Leader Bot 管理两个项目，也不会合并它们的上下文。

## 启用

在仅监听回环地址、单所有者且未启用 LiveShare 的 DSH Web 中使用。以 DSH `0.2.2-rc.5` 为基准，先在源码树执行 `pnpm build`，再按[隔离环境启动方式](managed-worker.md#在隔离环境启用)启用 Studio 宿主和三个预设。`stateDir` 必须是该 Studio 实例专用的绝对路径，例如 `/home/me/.dsh/agent-studio`。可选的 GitHub 工单服务使用独立目录，启用 Studio 时无需启动它。

GUI 使用 DSH 的所有者浏览器登录，不需额外的 Web Token。默认用宿主工作目录建立新的 Assistant Session，可用 `studioCwd` 指定绝对路径。不要将 DSH Web 暴露到公网。

## 从旧命名升级

保留现有 DSH 配置档。先停止旧版 Studio 接收新工作、等待在途轮次结束，再停用旧 bundle。旧 Studio 数据库为 `managed-worker.sqlite`；用 SQLite 的备份接口将完整数据库复制到尚未使用的新目录，并检查副本完整性，再将 `stateDir` 指向它。勿同时启用两个数据库副本，也不要在旧宿主持有目录锁时复制主文件。确认对话和任务可查前，保留原库与旧安装包用于回退。

宿主和预设使用 `agent-studio` 命名；迁移部署覆盖层时保留原有业务配置，只改对应的条目标识和数据目录。Studio 恢复已有 Assistant 或 Leader 会话时识别旧预设并记录新标识。旧 DSH 会话日志及其中的来源坐标、工作文件和外部作业不随 SQLite 迁移。

## 对话、话题与来源

- **发送**写入当前 Assistant 或项目对话，无需选择底层 Session。Assistant 可以在派工或等待确认时继续处理新请求；后台结果仍回到原消息或话题。项目交接后，新消息交给当前 Leader。之前的可见对话保持不变。
- **引用**附带原文片段，点击引用可跳回原消息，不创建话题。**回复**建立或接续以原消息为根的话题；点击主线上的回复入口即可回看话题，不展开进主时间线。
- 可以用任务名称、明确的原消息回复或任务 ID 指定要停止或改向的事项；另问一件事不取消原任务。对支持修订的普通文字任务，Studio 在原任务下保存结果，由无工具 Worker 执行。受管文档、长作业和带受保护证据的工作不走普通文字修订，也不会自动另行派工。
- **会话记录**可按 Session ID、项目 ID 或角色查找底层记录；消息和文字成果也可以通过「查看来源」直接查看对应事件。读取只打开日志，不唤醒角色、不提交消息，也不离开 Studio。

Studio 分配的底层 Session 不出现在浏览器普通工作区列表；Studio 宿主已登记的原生角色也按已绑定的身份排除，而不是按名称过滤。底层存储和 DSH 的 Session 索引保留。`0.2.2-rc.5` 没有 Workspaces 专用过滤接口，因此 Studio 在浏览器 Session 目录发布时过滤；原生全局内容搜索仍可能先受宿主返回条数限制。

## 模型设置

在 Studio 设置中分别选 Assistant、Leader 的默认 **Provider / 模型 / 思考深度**。保存时和每次发送前都会核对明确选定的组合。选「DSH 默认」则跟随宿主默认；未指定思考深度时按该模型的适配器默认。保存影响后续轮次，不打断正在运行的轮次；对话窗口没有临时模型切换。Worker 继续使用[派工模型配置](managed-worker.md#限定普通文字-worker-的模型组合)，不会被 Studio 对话设置直接覆盖。

## 绑定飞书 Assistant 私聊（可选）

准备一个独立的自建应用与机器人，在飞书配置长连接接收 `im.message.receive_v1` 和「卡片回传交互」`card.action.trigger`，开通以机器人身份发送、回复私聊与更新消息卡片所需的权限。验证机器人、操作者和私聊 ID 后，在 Studio 宿主条目 `agent-studio-managed-worker` 的 `config` 下填写下列字段；不用同时启用旧的 `feishuTextInbox` 或 `feishuDocumentInbox`。

```yaml
studioCwd: /absolute/path/to/workspace
feishuConversation:
  appId: cli_<app-id>
  botOpenId: ou_<bot-open-id>
  ownerOpenId: ou_<owner-open-id>
  chatId: oc_<private-chat-id>
```

启动时从宿主环境提供 `STUDIO_FEISHU_APP_SECRET`；不要保存到配置、日志或聊天。Studio 在实际验证机器人并建立长连接后记录绑定时间；同一绑定断线重连不会更换时间分界。解除、改变绑定并再次连接时重新划界，不导入绑定前的对话，也不执行旧消息。重启没有补捞断线期间的飞书历史；若发送回执无法确认，Studio 标为「未确认」，不会盲目重发。

两端共用 **Assistant** 的文字消息和话题。GUI 的用户消息以机器人身份同步，标作「你 · 来自 GUI」；飞书来信在 GUI 标出来源。GUI 中回复、在飞书原消息的话题中继续，或反过来，都会关联同一个话题。Leader、Worker 的内部消息和日志不会同步到飞书。

## 待我处理

入口徽标只统计需要你处理的事项，不为普通提问或底层 Session 活动加徽标。真正需要你决定的动作会在飞书私聊主聊天提示，不用打开原话题找卡片。网页和飞书都可以直接问「还有什么待我处理？」或「确认状态」，不调用模型。

对支持的确认（例如立项），可以直接回复确认消息说「批准」或「拒绝」，也可以在私聊明确说「批准创建项目 ××」。按钮不是必需的。单独发「好」、指向不清的决定以及已失效的旧答复都不会授权；确认只影响对应动作，批准记录也不代表动作已经执行。

一端处理后，另一端读取同一状态。飞书由机器人更新原卡片，纯文字通知则另发处理状态；如果宿主离线或更新未获确认，旧消息可能还没变化，可用文字查询。宿主需持续运行并能连接飞书，不要求浏览器一直打开。飞书客户端显示「已发送」不代表 Studio 已接收或执行。
