# 使用 Agent Studio

Agent Studio 是 DSH Web 左侧的独立入口。默认进入 **Assistant**，也可在项目列表选择活动项目，与它的现任 **Leader** 对话。各项目与 Assistant 分开保存对话；复用同一个 Leader Bot 也不会合并项目上下文。本指南说明截至阶段 4（自举无缝更新）的能力，现场核验范围见 [V1 验收清单与证据](progress.md#v1-验收清单与证据)。

## 启用

使用仅监听回环地址、单所有者且未启用 LiveShare 的 DSH Web。已在 DSH `0.2.2-rc.5` 的隔离配置档验证。Studio 使用 DSH Web 自带的所有者浏览器登录，不需要另外配置 Web Token；不要将该监听地址暴露到公网。

从源码试用时，先在仓库运行 `pnpm build`。将以下覆盖层保存到仓库外，替换 `stateDir` 为此 Studio 实例专用的绝对目录。示例禁用同一 bundle 的 GitHub Ticket 条目，仅用于隔离试用；已有 Ticket 实例不需要改动。

```yaml
- id: agent-studio
  disabled: true
- id: agent-studio-github
  disabled: true
- id: agent-studio-feishu
  disabled: true
- id: agent-studio-worker-preset
  disabled: true
- id: agent-studio-router-preset
  disabled: true
- id: agent-studio-managed-worker
  disabled: false
  config:
    stateDir: /home/me/.dsh/agent-studio-test-state
- id: agent-studio-assistant-preset
  disabled: false
- id: agent-studio-leader-preset
  disabled: false
- id: agent-studio-managed-worker-preset
  disabled: false
```

用独立的 `DSH_HOME` 从试用目录启动，先加载[仓库补丁](../../cordis.patch.yml)，再应用覆盖层。打开本次启动输出的回环地址。

```sh
DSH_HOME=/absolute/path/to/studio-test-home dsh --profile web \
  --patch /absolute/path/to/agent-studio/cordis.patch.yml \
  --patch /absolute/path/to/studio-local.yml \
  --host 127.0.0.1 --port 0 --no-open
```

如该 bundle 已安装到隔离配置档，只需应用覆盖层，不重复加载仓库补丁。`studioCwd` 可指定已存在的绝对目录；省略时使用宿主工作目录。它不移动已有 Session，也不授权 Worker 改动文件。

## 从旧版升级

先停止旧宿主接收新工作，等待在途轮次结束，再停用旧 bundle。用 SQLite 备份接口把 `managed-worker.sqlite` 完整复制到新目录，核对副本完整性，然后让当前版本的 `stateDir` 指向副本。不要复制仍由旧宿主持锁的主文件，不要同时运行两个副本。保留原库、旧配置档和旧安装包，供核对或回退；不要用旧程序打开已迁移的库。

首次打开 SQLite V0 或 V1 旧库时，宿主将其迁移到 V2（`user_version = 2`）。已发布对话、已有项目、对话模型设置和飞书绑定分界保留；普通已完成结果可查，旧在途执行标记为中断，不会自动重跑。V0 旧 Session 仅供查阅，不恢复为可执行身份；受保护结果不会进入现行任务与交付视图。SQLite 迁移不搬运 DSH 会话日志或本地工作文件。旧 `textWorkerRoutes` / `textWorkerDefaults` 只用于读取兼容，应用设置时写回新键；旧飞书收件配置不会替你启用共用对话，需要用户重新明确验证绑定。

## 自举更新与回滚

自举更新只作用于当前受管的 Linux DSH Web 配置档，不升级 DSH 本身。建议先在独立 `HOME`、`DSH_HOME`、命名 profile 和回环端口验收，不要用正在服务的配置档试验。部署者需事先准备：

- 在与源码、Studio 数据目录和 DSH 数据目录分开的 `<installRoot>/releases/<release>` 中放置已构建的发布（Host、Web Client 和运行资产）。`<installRoot>/current` 是指向该目录的唯一活动符号链接，配置档必须通过 `current` 加载 Studio；不要直接引用物理发布路径。安装根、`releases`、每套发布的根和 Studio 数据目录要求仅所有者可访问（`0700`）。提供发布所需的运行时依赖，并保持 profile 所用依赖和运行入口在切换后可解析；依赖不随发布指针切换。发布内的运行资产不得是符号链接。为 `<stateDir>/runtime/health.sock` 选择足够短的绝对路径。
- 在 `agent-studio-managed-worker.config` 登记下例中的 `selfUpdate`，它不是 Web 可写配置。`repoPath` 必须是专用、受信的 Agent Studio Git 仓库根；构建会读取已跟踪及未忽略的工作树字节（包括未提交修改），但不会运行 Git hooks 或改写原工作树。若从项目入口准备更新，项目必须绑定这个规范路径，管理轮次也必须仍有效。控制器在临时工作树按锁文件安装依赖（禁用安装脚本）并运行真实 `pnpm check`。部署者须保证可信工具与注册表可用；新建构建 HOME 并不等同于对不可信源码做 OS 级隔离。
- `reloadCommand` 是部署者固定的 argv，不经过 shell。它必须直接启动并保留当前 profile 的 DSH PID（避免 daemonize 或用不 `exec` 的包装脚本），用同一回环端口，不能包含 `--from-default-profile`。飞书已配置时，App Secret 必须在 DSH 凭据库中保存；仅启动时注入的密钥不能用于受管重载。缺少可用重载配方时可准备候选，但不能批准切换。

```yaml
selfUpdate:
  repoPath: /absolute/path/to/trusted-agent-studio-repo
  installRoot: /absolute/path/to/studio-install
  healthTimeoutMs: 30000
  reloadCommand:
    executable: /absolute/path/to/node
    args: [/absolute/path/to/installed/dsh/lib/bin.js, --profile, studio, --host, 127.0.0.1, --port, '3080', --no-open]
    cwd: /absolute/path/to/studio-workspace
    profileName: studio
    dshHome: /absolute/path/to/studio-dsh-home
```

1. 打开 **Studio 设置 → 更新**，核对宿主版本、构建 ID、指纹和浏览器构建 ID。选已登记源码或使用该源码的活动项目，点 **准备更新**。前置检查完成才创建一条有时限的「待我处理」确认；失败（`failed_precheck`）没有待办，也不停止旧宿主或修改指针。
2. 在更新页或统一待办核对当前指纹和候选指纹，再明确 **批准更新** 或 **取消更新**。已配置飞书时可在绑定的私聊卡片或明确回复处理同一待办；两个入口只有一个决定生效，旧确认不能补交重放。批准后宿主停止接收新写入，等待在途工作与出箱排空并封存 SQLite WAL。脱离控制器核对封存回执和旧进程身份，确认旧 PID 已退出后才原子替换 `current` 并重启同一配置档。排空或交接失败不会切换发布。
3. `GET /agent-studio/health` 仅允许 DSH 所有者浏览器登录及 Studio 请求标头，返回构建标识、PID、就绪与阶段、SQLite、配置和飞书状态，不含路径、凭据或消息，不触发写入。控制器使用私有 Unix socket 的随机挑战核验新 PID、预期构建和指纹；浏览器显示版本不一致时手动刷新页面，不重发上次决定。
4. 切换或启动核验失败时，控制器终止失败候选，原子切回已验证基线并重新检查；成功记为 `rolled_back`。基线也无法恢复时记为 `recovery_required`，不循环重启：保留数据、发布与 `state.json`，按设置页的脱敏 `updates/<updateId>/controller.log` 引用在数据目录查看私有日志，再由部署者处理。成功更新后，设置页可针对该次保留的基线**申请回滚**，但仍必须批准一条全新的确认才切换，不会回滚或覆盖共享数据库。

## 对话、项目和任务

| 角色 | 当前职责与限制 |
| --- | --- |
| **Assistant** | 直接回答简单问题、概念解释和一般状态说明；把需要独立执行的未立项请求登记为后台任务，把明确指给现有项目的请求转交其现任 Leader。只在所有者要求新立项时提出确认。 |
| **Leader** | 在本项目对话、组织工作、派工和查询成果；项目换任或归档后，原任 Session 不再拥有管理权。 |
| **Worker** | 仅处理经过登记的当前任务，不转委派。未绑定工作区时只处理文字；绑定后，按本任务的权限档位调查、修改或运行检查。 |

- **发送**写入当前对话，不必先选择底层 Session。Assistant 委派后台任务或等候确认时仍可接收其他请求；另问一件事不会自动取消旧任务。**引用**附带可跳回的原文片段，不新建话题；**回复**建立或接续以原消息为根的话题。
- **指名转交：**在 Web Assistant 或已绑定的飞书私聊说「请让现有项目『项目名』检查……」。使用准确的项目名称或 ID；有歧义时指出具体项目。Studio 将认证原文交给现任 Leader，同一条消息不会重复登记；归档项目须先重新开启。受理回执带追踪号，Leader 的最终回复或派生任务的关键状态与交付摘要回到原消息或话题，不同步项目内部步骤和日志。受理或对话已处理不等于任务已交付。
- **会话记录**可按 Session ID、项目 ID 或角色查找；消息或任务可用「查看来源」只读核对 Session 和对应日志，读取不唤醒会话、不提交消息。Studio 管理的 Session 从浏览器普通工作区列表隐藏，原生存储和索引仍保留；该过滤不是对 DSH 全局搜索结果的承诺。

### 统一任务面板

打开 **任务**，可按「全部／进行中／已结束」与「全部对话／Assistant／指定项目」组合筛选。账本区分七态：排队中（`queued`）、执行中（`running`）、等待确认（`waiting_approval`）、受阻（`blocked`）、已中断（`interrupted`）、已取消（`cancelled`）、已交付（`delivered`）。申请写入的任务在批准之前已经可见，但 Worker 尚未取得执行授权。

展开条目可以查看任务 ID、原请求、结果摘要、工作区与权限、改动文件，以及实际检查命令、退出码和总体结论。可点「查看来源」只读打开对应记录，或对在途任务点「停止任务」。停止只作用于该任务 ID，也让它未处理的写入确认失效，不影响其他任务；不撤回已经发生的改动或重放原执行。也可用「最近任务」「查询任务 `<任务 ID>`」「停止任务 `<任务 ID>`」或原生命令 `/studio-result <task-id>` 核对和控制。

### 项目管理与归档

在项目导航点 **新建项目**，填写名称、目标及可选的绝对工作区目录。创建后进入新项目；Leader 在收到请求前不会工作。在活跃项目点 **管理项目** 可编辑名称、目标或工作区，清空工作区并保存即解绑。「更换负责人」（Leader）与「归档项目」都需二次确认。工作区改绑、换任或归档会推进项目的管理轮次、撤销在途工作的旧授权；换任或归档使原 Leader Session 失去管理权，单纯改绑则保留 Session、冻结旧轮次。旧表单或确认若落在过期轮次不会覆盖新状态。

从导航的 **已归档项目** 可打开只读对话和档案。归档保留历史但不接受新工作；点 **重新开启** 后由新 Leader 接收新消息，不恢复旧授权或重放任务。原生命令 `/studio-project` 仍可管理项目和档案。

### 项目档案与显式偏好

- **项目档案**保存决定、进展和未决事项。在活跃项目中打开「项目档案」编辑保存；归档后只读。档案跟随项目，不跟随旧 Leader，会随同项目目标和工作区注入现任 Leader 的后续轮次。
- **偏好设置**只记录所有者明确保存的内容，不从日常对话自行累积。打开左侧「偏好」（或项目管理中的「项目偏好」），选择全局或当前项目范围；增添带稳定键的偏好，或编辑现有行的版本。忘记须二次确认；忘记后正文被清空、从活跃列表移除，旧版本不会覆盖或复活它。项目归档后该项目的偏好只读。原生命令 `/studio-memory` 仍可管理明确偏好。
- Assistant 的动态系统上下文只加入全局活跃偏好；Leader 加入全局和本项目活跃偏好及本项目档案。其他项目的档案／偏好、已忘记的偏好及其墓碑不注入。参考资料不等于当前任务授权。

## 本地工作区与派工授权

- **未立项调查：**在发给 Assistant 的当前请求中写出宿主上已存在的绝对目录，例如「请只读调查 `/home/me/projects/example`，给出文件路径和行号，不立项」。没有绑定时任务是纯文字，不会用 `studioCwd` 代替任务工作区；绑定失败也不会回退。派工不会自动创建项目。
- **绑定项目：**新建或编辑项目时可填写绝对目录，也可在要求 Assistant 新立项的原文中给出目录，并在确认中核对。通过原生命令更新的示例：`/studio-project update {"projectId":"<项目 ID>","epoch":1,"workspacePath":"/home/me/projects/example"}`。用当前管理轮次，`workspacePath: null` 可解除绑定。现任 Leader 派工时使用项目已绑定的目录，不能换成另一个目录。工作区会规范化；根目录、家目录和受保护位置（如 `~/.ssh`、`~/.dsh`、自定义 `$DSH_HOME`、实际 DSH 配置档的数据与配置位置及 Studio 数据目录）不能作为任务工作区。

| 任务权限 | 有工作区时可做什么 |
| --- | --- |
| `read-only`（默认） | 只允许原生列目录、文件和图片读取、按模式搜索（`studio_list_directory`、`read`、`read_image`、`glob`、`grep`）。没有 Shell，包括 `bash` 和 `pwsh`。 |
| `workspace-write`（逐任务确认） | 用 `write` / `edit` 创建或修改工作区文件，执行允许的单条查看命令或本地检查，如 `pnpm check`、`pnpm test`。Shell 不直接允许 `rm`、`mv`、`cp`；Git 命令也会检查仓库配置，拦截可能执行外部 helper 的配置。必须由所有者在本轮确认中选择「允许本任务写入」；确认列出规范目录和任务原文。已有项目绑定、配置默认值及过去的批准均不授予此权限。 |

结果中的**宿主执行收据**列出已观测的 `write`/`edit` 相对路径，以及实际检查、工作目录、退出码、超时或中止状态。只有测试、类型检查、构建、lint 等检查计入总体状态；`pwd`、`ls`、`git status` 等查看命令不计入。任一实际检查失败，总体状态就是 `failed`；未运行检查则是 `not_run`。手动停止不会撤回已有改动，但会保存已观测的改动和检查，并把已派发尚未回报的检查记为中止。收据不是整个目录的差异报告，不枚举项目脚本间接生成的所有文件。Worker 正文单独显示，即使正文说「全部通过」，也不算宿主证据。可在原话题或用 `/studio-result <task-id>` 核对已保存的结果。

Studio 在工具生效前核验当前 Session 工作目录、路径和命令，并用 DSH 沙箱约束写入。越界符号链接不会被读取，写入路径不能经过符号链接；提权、网络工具、发布或推送等不在许可范围内。遇到需所有者决定的操作，旧执行会立即撤权，即使待办已满或通知无法写入也不会继续。如果未生成待办，可手动停止该任务；解除等待不会恢复权限或重放旧操作。**这不是任意不可信项目的隔离环境**：DSH `0.2.2-rc.5` 的原生 POSIX 沙箱没有完整隔离项目脚本的网络访问。只在可信工作区运行确认过的项目脚本。

## Studio 设置

从 **Agent Studio → Studio 设置** 打开。设置作用于当前 DSH Web 配置档，不是单项目配置。跨分类编辑保留草稿；离开前可选择继续编辑或放弃。如果当前配置档不可写、修订已过期，或更高优先级的配置覆盖了相同字段，Studio 不会报告应用成功。

| 分类 | 可配置内容 | 生效方式 |
| --- | --- | --- |
| 对话模型 | Assistant、Leader 各自的默认提供方、模型和思考深度，也可用 DSH 默认 | 即时保存，用于后续轮次，不改变 Worker 路由。 |
| Worker 派工 | 带唯一 ID 的模型路由（`workerModelRoutes`）、按发起角色指定默认路由 ID（`workerModelDefaults`），以及 `defaultWorkerPermission` | 未设角色默认时先匹配对话模型，再选清单首项；清单为空则用对话模型。`defaultWorkerPermission` 为兼容旧配置保留；未明确请求写入的派工仍按 `read-only`，指定 `workspace-write` 也必须逐任务由所有者确认。 |
| 飞书 | 停用，或绑定专用机器人私聊、共用 Assistant 对话 | 私聊验证与保存分开。设置已应用不等于已连通或单条消息已送达。 |
| 高级 | 新 Assistant Session 的工作目录、尚未保存对话模型时的初始值、Studio 数据目录 | 工作目录不移动现有 Session；初始值不覆盖已保存的模型；更换数据目录须另行确认。 |

除「对话模型」即时保存外，其余配置使用**检查并应用设置**，可能重载 Studio 宿主并重新连接飞书，不需要重启整个 DSH Web。在途工作会阻止重载。回执不明确时，先用「核对当前设置」读取实际值，不要重复提交。

### 更换 Studio 数据目录

在「高级」中填写一个**尚不存在**的绝对目标目录；其上级目录必须已存在，不经符号链接，不可由其他用户写入。选择**复制当前 Studio 数据库**或**使用空的 Studio 数据库**，再原样输入路径确认。复制保留 Studio 数据并留存原库；空库不导入历史，两种方式均不移动 DSH 会话日志或工作文件。若切换未确认，先核对实际路径，不要复用可能只准备了一部分的目标目录，也不要让新旧两份账本并行运行。

## 绑定飞书 Assistant 私聊（可选）

1. 在飞书开放平台准备专用自建应用与机器人，启用长连接、`im.message.receive_v1` 和 `card.action.trigger`，开通所需的私聊收发、回复和卡片更新权限后发布。同一应用不要同时让多个宿主接收长连接事件。
2. 点 **配置飞书** 或进入 **Studio 设置 → 飞书**，选择共用 Assistant 对话。填写应用 ID 和 App Secret，点 **验证私聊**；按提示在机器人私聊原样发送一次性验证消息。验证会核对机器人、操作者和私聊 ID；验证消息不会进入对话或触发派工。
3. 点 **检查并应用设置**，然后查看连接状态。App Secret 只写入 DSH 凭据存储，不回显；不要写入普通设置、日志或聊天。轮换密钥时先输入新值并验证再应用。解绑后停止新同步，不撤回已发的飞书消息，也不删除 Studio 记录。

同一绑定断线重连不改变初始时间分界，解绑或换绑后重新划界；不导入绑定前历史，也不自动补捞断线期间的飞书历史。不能确认的出站记录标为「未确认」，不会盲目重发。私聊验证只证明入站身份和路径；投递和卡片权限以实际结果为准。

共用对话同步 **Assistant** 的文字消息、话题和支持的确认，也投递指名项目转发的关键回执。GUI 用户消息以机器人身份标注「你 · 来自 GUI」，飞书来信在 GUI 标出来源；Leader 和 Worker 的内部消息及日志不向飞书同步。

### 查询受理与补交

- 回复原消息发送「查询受理」，或发送「查询受理 `<Studio 消息 ID 或转发追踪号>`」。在 Assistant 还可指定飞书消息的准确 ID，例如「查询受理 `om_…`」。回执分别报告是否受理、对话轮次、转发阶段和已登记任务的状态；飞书显示「已发送」、Studio 已登记或对话已处理，都不等于任务已交付。
- 若断线时的消息经查询确认尚未登记，可在 Assistant 发送「补交消息 `<飞书消息 ID>`」。宿主只查这条消息，核验当前机器人、所有者和私聊，只接受绑定分界后的合格文字消息。同一消息多次补交仍只登记一次；绑定前消息、无权查证的消息、没有可识别父消息的回复、旧确认或控制指令都不能用这条路径回放，需另发新消息。

## 待我处理

徽标只统计需要所有者处理的事项，不统计普通提问或 Session 活动。支持移动端的确认在飞书私聊主聊天提示；不支持移动端的事项（如任务阻塞）仍须在 Web 处理。Web 与飞书可问「还有什么待我处理？」核对状态，不调用模型。

对支持文字确认的事项，可直接回复对应消息说「批准」或「拒绝」，或明确说出要批准的立项。单独发「好」、指向不清或已失效的答复不能授权。批准只影响对应事项，不等于动作已执行。一端处理后，另一端读取同一状态；若飞书卡片更新不明确，可用文字查询。飞书客户端显示「已发送」不等于 Studio 已受理或执行。

**Worker 拦截待办不是批准入口。** 越界或高危动作被守卫拦下并登记为 `guard-intercept:` 待办时，旧执行已撤权，任务进入 `waiting_approval`。在 Web 或已绑定的飞书私聊选择「取消任务」（`cancelled`）或「仅解除等待（不重放被拒动作）」（`interrupted`）；也可在原卡片下回复这两种明确决定，或附上确切的待办 ID。没有「仍然执行」选项，过期或重复答复不改变任务。如需继续，请另发合规的新请求；此前已经完成的修改也不会因此回滚。
