# 使用 Agent Studio

Agent Studio 是 DSH Web 左侧独立入口，不是普通工作区。打开后默认进入 **Assistant**，可从项目列表切到当前 **Leader**。Assistant 和各个项目分别保存对话；同一个 Leader Bot 管理两个项目，也不会合并它们的上下文。

## 启用

在仅监听回环地址、单所有者且未启用 LiveShare 的 DSH Web 中使用。以 DSH `0.2.2-rc.5` 为基准，先在源码树执行 `pnpm build`，再按[隔离环境启动方式](managed-worker.md#在隔离环境启用)启用 Studio 宿主和三个预设。`stateDir` 必须是该 Studio 实例专用的绝对路径，例如 `/home/me/.dsh/agent-studio`。可选的 GitHub 工单服务使用独立目录，启用 Studio 时无需启动它。

GUI 使用 DSH 的所有者浏览器登录，不需额外的 Web Token。默认用宿主工作目录建立新的 Assistant Session，可用 `studioCwd` 指定绝对路径。不要将 DSH Web 暴露到公网。

## 从旧命名升级

保留现有 DSH 配置档。先停止旧版 Studio 接收新工作、等待在途轮次结束，再停用旧 bundle。旧 Studio 数据库为 `managed-worker.sqlite`；用 SQLite 的备份接口将完整数据库复制到尚未使用的新目录，并检查副本完整性，再将 `stateDir` 指向它。勿同时启用两个数据库副本，也不要在旧宿主持有目录锁时复制主文件。确认对话和任务可查前，保留原库与旧安装包用于回退。

宿主和预设使用 `agent-studio` 命名；迁移部署覆盖层时保留原有业务配置，只改对应的条目标识和数据目录。Studio 恢复已有 Assistant 或 Leader 会话时识别旧预设并记录新标识。旧 DSH 会话日志及其中的来源坐标、工作文件和外部作业不随 SQLite 迁移。

## 对话、话题与来源

- **发送**写入当前 Assistant 或项目对话，无需选择底层 Session。Assistant 可以在派工或等待确认时继续处理新请求；后台结果仍回到原消息或话题。项目交接后，新消息交给当前 Leader。之前的可见对话保持不变。
- **引用**附带原文片段，点击引用可跳回原消息，不创建话题。**回复**建立或接续以原消息为根的话题；点击主线上的回复入口即可回看话题，不展开进主时间线。
- 可以用任务名称、明确的原消息回复或任务 ID 指定要停止或改向的事项；另问一件事不取消原任务。对支持修订的普通文字任务，Studio 在原任务下保存结果，由无工具 Worker 执行。受管文档、长作业和带受保护证据的工作不走普通文字修订，也不会自动另行派工。
- **会话记录**可按 Session ID、项目 ID 或角色查找底层记录；消息和文字成果也可以通过「查看来源」直接查看对应事件。读取只打开日志，不唤醒角色、不提交消息，也不离开 Studio。

Studio 分配的底层 Session 不出现在浏览器普通工作区列表；Studio 宿主已登记的原生角色也按已绑定的身份排除，而不是按名称过滤。底层存储和 DSH 的 Session 索引保留。`0.2.2-rc.5` 没有 Workspaces 专用过滤接口，因此 Studio 在浏览器 Session 目录发布时过滤；原生全局内容搜索仍可能先受宿主返回条数限制。

## Studio 设置

从 **Agent Studio → Studio 设置** 打开。日常配置不用改 YAML；设置只作用于启动当前 DSH Web 的配置档，不作用于单个项目。跨分类编辑不会丢弃草稿，离开 Studio 设置前可选择继续编辑或放弃。一个更高优先级的宿主配置覆盖设置、当前配置档不可写或有其他修改时，Studio 不报告应用成功。

| 分类 | 可配置内容 | 生效方式 |
| --- | --- | --- |
| 对话模型 | Assistant、Leader 各自的默认提供方、模型和思考深度；可使用 DSH 默认 | 保存后用于后续轮次，不打断当前工作，不改 Worker 派工。 |
| 派工与顾问 | 普通文字 Worker 的有序组合清单、两种派工角色各自的默认值及上下界；Advisor 路由 | 组合必须同时指定提供方、模型和思考深度，范围引用同一清单；未配置时沿用[原派工规则](managed-worker.md#限定普通文字-worker-的模型组合)。 |
| 飞书 | 三种互斥模式、私聊绑定、密钥、文字任务路由和文档更正选项 | 验证与保存分开。配置生效不代表飞书已连接，也不等于单条消息已送达。 |
| 文档与记忆 | Web 文档消息登记、文档接续、记忆与项目档案 | 关闭不删除记录，不会清除已经生效的文档授权限制或待核对事项。 |
| 监督与作业 | 共享额度池、飞书告警、Watchdog、文档任务接替、关联已有作业及轮询秒数 | 文档接替依赖 Watchdog；告警依赖相应飞书收件模式。作业观察的 `0` 表示不轮询，非零使用 `5–300` 的整数。 |
| 高级 | 新 Assistant 会话的工作目录、对话模型尚未保存时的宿主初始值、Studio 数据目录 | 工作目录不移动已有会话；初始值不覆盖已保存的角色模型。更换数据目录须单独确认。 |

除了「对话模型」的即时保存，其余设置使用**检查并应用设置**，会重新加载 Studio 服务并在需要时重新连接飞书；不重启整个 DSH Web，也不停止外部作业。排队或运行中的 Studio 工作会阻止应用。已停止的额度池不会因改名、删映射或切换空数据库而被绕过。若回执丢失，先用「核对当前设置」读取实际生效值，不重复提交。

### 更换 Studio 数据目录

在「高级」中填写一个**尚不存在**的绝对目标目录。上级目录应已存在、不经符号链接且不可由其他用户写入。选择**复制当前 Studio 数据库**或**使用空的 Studio 数据库**，再原样输入目标路径确认。复制保留 Studio 对话、项目、待办和授权账本，运行中的写入先停止、数据库副本通过核对后才启用；原库留作备份。空库从无 Studio 记录开始，旧库不删除。两种方式都不移动 DSH 会话日志、工作文件或外部作业。若切换未确认，核对当前路径，不复用可能只准备了一部分的目标目录，不把新旧两份账本并行运行。

## 绑定飞书 Assistant 私聊（可选）

1. 在飞书开放平台准备一个专用的自建应用与机器人，启用长连接与 `im.message.receive_v1`，开通私聊机器人所需的发送、接收和回复权限并发布应用。共用 Assistant 对话还需要启用「卡片回传交互」`card.action.trigger` 和卡片更新权限。同一应用不要同时由多个宿主接收长连接事件。
2. 在 Studio 顶部点 **配置飞书**，或进入 **Studio 设置 → 飞书**。选择共用 Assistant 对话、文档核对收件或文字任务收件。后两种是独立的收件模式；不能和共用对话同时开启。文字任务模式还需要指定工作目录和模型，也可以开启已绑定文档的更正。
3. 填写应用 ID 和 App Secret，点 **验证私聊**。按页面提示在飞书私聊机器人，原样发送一次性验证消息。GUI 从该消息核对并补全机器人、操作者和私聊 ID；已经填写的 ID 必须匹配。验证消息不会加入 Studio 对话、派工或触发回复。
4. **检查并应用设置**，然后在同一页查看连接状态。App Secret 只写入 DSH 的凭据存储，不回显；不要把它写入普通设置、日志或聊天。轮换密钥时在同一页输入新密钥并验证后再应用；已有启动环境配置仍可用。若旧连接离线、无法用同一应用收到验证码，先检查长连接；必要时解除旧绑定后再验证。解除绑定停止新的同步或卡片操作，不撤回飞书消息，也不删除 Studio 记录。

Studio 在验证机器人并实际连接后记录绑定时间。同一绑定断线重连不更换时间分界；解除绑定或更换绑定并再次连接时重新划界，不导入绑定前的对话。重启不会补捞断线期间的飞书历史；若发送回执无法确认，Studio 标为「未确认」，不盲目重发。私聊验证只证明入站身份和消息路径；出站投递、卡片权限要按实际使用结果分别核对。

共用对话时同步 **Assistant** 的文字消息和话题。GUI 的用户消息以机器人身份同步，标作「你 · 来自 GUI」；飞书来信在 GUI 标出来源。两端回复同一话题会关联到一起。Leader 和 Worker 的内部消息及日志不会同步。

## 待我处理

入口徽标只统计需要你处理的事项，不为普通提问或底层 Session 活动加徽标。真正需要你决定的动作会在飞书私聊主聊天提示，不用打开原话题找卡片。网页和飞书都可以直接问「还有什么待我处理？」或「确认状态」，不调用模型。

对支持的确认（例如立项），可以直接回复确认消息说「批准」或「拒绝」，也可以在私聊明确说「批准创建项目 ××」。按钮不是必需的。单独发「好」、指向不清的决定以及已失效的旧答复都不会授权；确认只影响对应动作，批准记录也不代表动作已经执行。

一端处理后，另一端读取同一状态。飞书由机器人更新原卡片，纯文字通知则另发处理状态；如果宿主离线或更新未获确认，旧消息可能还没变化，可用文字查询。宿主需持续运行并能连接飞书，不要求浏览器一直打开。飞书客户端显示「已发送」不代表 Studio 已接收或执行。
