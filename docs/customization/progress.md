## 实施顺序

| 顺序 | 工作 | 通过标准 |
| --- | --- | --- |
| **1 · 第一个可用版本（通过隔离 Web 宿主验证）** | 在隔离环境跑通 GUI → Assistant 委派 → 受管 Worker → 原入口取得成果。建立稳定的 Bot、任务和会话标识，先支持一种受管资源。 | 普通文字任务不依赖 GitHub，Assistant 不代做；成果可追溯到 Worker，结束会话后仍可取；暂停和移交仍能阻止旧动作。 |
| **2 · 持续项目与跨入口更正（文档主流程通过隔离验证）** | 增加明确立项和 Leader 当前管理权。GUI 与飞书共用指令登记，处理自然语言更正、重复和迟到的指令、共享文档冲突。 | 换入口更正后接续原任务；旧 Leader 不能再派工，旧 Worker 不能再推进；并发修改不静默覆盖。 |
| **并行 · 额度与长作业（停止与接续通过隔离验证）** | 验证共享额度池耗尽后底层业务重试确实停止；另选一条现有外部作业路径，验证其跨工作室重启并按条件接续。 | 通知不依赖耗尽的模型；等待释放 Worker 槽位，完成观察不重复接续、不覆盖人工暂停。 |

### 第 1 步的验证范围

- [从源码树隔离启动](<managed-worker.md#从源码树试用>)：独立 Web profile 实测真实 bundle 补丁加本地覆盖层，原型条目保持禁用，三个 Studio 预设沿用仓库配置。Leader 可通过原生命令立项，Assistant 向一个无工具 Worker 委派原请求并取回已保存成果。
- [普通文字任务](<managed-worker.md#交代文字任务和取回成果>)：DSH `0.2.2-rc.3` 单所有者宿主通过原生 Web RPC 接收消息，用本地固定响应模型验证一次委派、同消息去重、原入口成果与 Worker 来源一致。Web 实时订阅与历史读取收到相同的 `Worker result` 卡片正文和出处，给 Assistant 的工具回执只含摘要与出处。Worker 会话结束和宿主重启后仍能取回原文，取回不调用模型。已在独立浏览器展开 `Worker result`，核对表格原文、任务 ID 和 Worker 出处。改用 DSH 原生工具结果收尾后，在独立 profile 用 `deepseek-official/deepseek-flash` 线上复验通过：Assistant 派工和无工具 Worker 各发出一次请求，均返回 HTTP `200`，原轮次正常结束。按同一任务 ID 取回时，原文和出处均与卡片一致，未发起新的推理。
- [普通文字 Worker 的组合限制](<managed-worker.md#限定普通文字-worker-的模型组合>)：独立 Web profile 验证 Assistant 委派和 Leader 手动派工只用清单中的深度；清单外不启动 Worker，已核实的深度在实际调用前失效时不进入适配器推理，也不改用其他组合。
- [两角色各自的文字派工默认组合](<managed-worker.md#限定普通文字-worker-的模型组合>)：独立 Web profile 验证双方各用配置的 Worker 组合，不改变发起会话；缺省时沿用本会话，已配置组合失效时不派工或回退。
- [按清单顺序限定角色范围](<managed-worker.md#限定普通文字-worker-的模型组合>)：独立 Web profile 验证两角色的端点组合可派工，显式选择或适配器默认深度越界时不启动 Worker、不自动换组合。
- [未立项的分项调查与整合](<managed-worker.md#未立项的分项调查与整合>)：独立 Web profile 验证两个无工具 Worker 分别调查、第三个 Worker 根据已保存的原文和出处整合，不创建项目。单项失败时不启动整合；重启后可无模型取回成功的整合结果或失败任务的部分成果。
- [受管文档](<managed-worker.md#文档写入控制>)是首个可变资源，只允许替换已登记的正文和版本。普通文字请求不能授予写入权；Assistant 没有业务工具，起草文字的 Worker 没有工具。原型 GitHub 路径保持不变。
- [暂停与重启保护](<managed-worker.md#宿主重启>)：验证过暂停事务回滚后重启仍阻止旧写入；接入 Assistant 后复验暂停、移交和显式恢复，旧 Worker 在移交及重启后均被拒绝，当前轮次只提交一次。
- [状态目录独占](<managed-worker.md#宿主重启>)：两个隔离 Web 宿主指向同一测试目录时，后启动者能打开 Web，但 Studio 加载被拒，不注册 Studio 命令，也不改业务记录；原宿主保持同一运行 ID，正常派工并交付一次。

### 第 2 步当前范围

- [项目管理权](<managed-worker.md#建立项目与移交管理权>)：所有者可用原生命令创建项目、复用 Leader Bot 或移交当前管理会话。隔离 Web RPC 验证同一 Bot 的管理轮次 `1 → 2` 后，原先已获准的旧调用也不能登记；旧会话重启后只读，重复输入未新增待办。
- [GUI 文档消息登记](<managed-worker.md#普通消息待核对>)：隔离试用验证原生 Web 收件先保存来源并阻止旧写入，不依赖 Worker 阅读；重投只登记一次，重启后待核对项仍阻止写入。SQLite 登记回滚的对照也验证了不报空箱、重开后保守暂停。登记本身不改变授权范围，所有者在 Web 核对实际效果。
- [飞书私聊登记](<managed-worker.md#飞书私聊登记>)：白名单私聊显式绑定原文档任务，与 GUI 共用待核对列表。独立 profile 用本地模拟 CLI 验证拒收错误身份和群聊、去重、待核对时阻止旧写入及重启后取回。Web 已确认收紧范围后，迟到飞书消息既不能再次收紧，也不能重投换正文；所有者核实保留现行范围后，另行续做才提交一次。未验证真实飞书送达，不补收断线期间的历史。
- [缩小修改范围并继续原任务](<managed-worker.md#缩小修改范围并继续原任务>)：独立 Web profile 中，从模拟飞书收件，在 GUI 确认只保留部分原批准行；过期确认与已获批的旧写入都被拒，同一 Worker 按新授权只写一次。在独立浏览器直接发起更正，已看到取消不改授权、确认后范围收紧的回执；只读核对确认仅保留第 1 行的许可，正文未写。原生复验另确认旧授权被拒，按新授权续做才写入获准的行。另用临时 SQLite 核对了窄化事务回滚和暂停保持。
- [共享文档](<managed-worker.md#多个任务修改同一文档>)：独立 Web profile 中，两条已经获批的任务写入竞争同一修订时，只有先提交的一条成功；人工先保存时，旧 Worker 及旧版人工保存也都报冲突。SQLite 保留三个有出处的修订，没有覆盖或多出一次工具提交。
- [Leader 派工和取回](<managed-worker.md#建立项目与移交管理权>)：独立 Web profile 中，旧 Leader 已过 Guard 的派工在移交后仍被拒；现任 Leader 让无工具 Worker 执行同一已登记待办。重投没有第二次执行，重启后仍可读取原文和结果出处。
- [文字派工诊断](<managed-worker.md#查看文字派工为何未完成>)：独立 Web profile 验证路线无法核实与原因未明分别显示；重复读取不派工，移交后由现任 Leader 查看诊断。
- [标记文字待办受阻](<managed-worker.md#标记文字待办受阻>)：独立 Web profile 验证受阻持续到移交，只有现任 Leader 能按 ID 解除；解除不执行，另发独立派工消息才启动 Worker。
- [单项待办选择一次派工模型](<managed-worker.md#为一项待办选择一次派工模型>)：独立 Web profile 验证保存与撤销不调用模型；带确切选择 ID 的新消息只派工一次，缺失、撤销或已用的选择均不回退。
- [自然语言立项](<managed-worker.md#建立项目与移交管理权>)：独立 Web profile 的原生问答验证了引文不符、拒绝、确认和重投；只有所有者确认才创建项目及独立 Leader，不会派工。
- [自然语言更正](<managed-worker.md#缩小修改范围并继续原任务>)：独立 Web profile 用模拟飞书验证了同任务收件、取消、过期确认及现版生效；建议不调用模型，旧批准不能写入，原 Worker 按新范围只提交一次。
- [飞书文字任务和同入口更正](<managed-worker.md#从飞书发起文字任务并取回>)：独立 Web profile 用模拟飞书验证了无工具派工和两入口无模型取回。同一私聊可兼顾文档更正；更换重复消息的正文不能改变原路由，迟到的文字任务不会派工。按官方 CLI `v1.0.90` 事件格式复验，纯文字保留父消息出处，富文本仅保留来源待核对，不派工。纯文字模式下，忙碌时被拒的消息在空闲后和重启后重投均不派工，另发的新消息正常完成。另以临时 SQLite 验证了旧记录兼容、重启及切回旧模式不重放。未连接真实飞书。
- [官方 SDK 直连](<managed-worker.md#飞书私聊登记>)：独立 Web profile 用官方 SDK `1.76.0` 和模拟网络验证了解析 v2 事件、一次无工具派工、向原消息发出两次不同幂等键的线程回复请求，以及按同一任务 ID 取回原文。本机 TLS 对端验证了 WebSocket 握手、二进制事件确认和取消握手时关闭连接。另用模拟 v2 事件验证了应用、用户或私聊不匹配时不登记、不派工、不回复。未连接飞书服务。
- [飞书与 Web 成果交接](<managed-worker.md#现场验收飞书与-web-的成果交接>)：独立 Web profile 通过官方 SDK 实收专用飞书私聊，原消息下显示登记和完成回复。文字 Worker 退出后，在新的 Studio Assistant 会话展开 `/studio-result` 回执，同一任务 ID、保存正文和 Worker 出处均一致，取回不再派工。使用本地固定响应，未验证线上模型输出。
- [飞书回复缺失后的取回](<managed-worker.md#从飞书发起文字任务并取回>)：独立 Web profile 用模拟 CLI 让接受和完成回复都失败；重启后从当前私聊的只读清单找到原任务并取回正文和出处，未重发或再次推理，换私聊配置后不再列出原任务。
- [持续项目文档接续](<managed-worker.md#项目待办关联文档任务>)：独立 Web profile 中，从自然语言确认立项、登记待办到飞书收紧范围，已过 Guard 的旧写入被拒；原 Worker 只提交一次。移交 Leader、共享文档再更新后，Web 仍按原待办取回实际提交的正文和出处，不调用模型。
- [查看已生效的文档范围更正](<managed-worker.md#查看已生效的文档范围更正>)：独立 Web profile 验证待核对不当作决定，生效后可查版本和原消息出处；移交后只有现任 Leader 能查询这段历史，同 Bot 的其他项目不可见。
- [跨入口继续原文档任务](<managed-worker.md#从-web-或飞书继续同一个文档任务>)：独立 Web profile 和模拟飞书验证 Web 多候选时不代选，私聊只接续已绑定的任务；暂停期间拒绝的旧消息重投不启动，原 Worker 按现行授权只写入一次。
- [查证文档写入为何未放行](<managed-worker.md#查看文档写入为何未放行>)：独立 Web profile 验证超范围、已过守卫后暂停和提交故障分别记录、均未改正文。另在初审读取注入一次存储故障，原生回执标为未核实而非范围拒绝，同版本续做不重放。故障解除后，在未启用 GUI 收件的对照中，新消息按原授权提交一次。
- [复核文档范围拒绝](<managed-worker.md#复核明确的文档范围拒绝>)：独立 Web profile 验证按原生调用复核同一版本只记录一次，换证据也不能再复核；临时 SQLite 夹具模拟初审误判，复核发现矛盾但未签发许可或写入。
- [独立 Advisor 咨询](<managed-worker.md#按需咨询-advisor>)：独立 Web profile 验证 Assistant 和现任 Leader 均可发起，实际调用使用指定模型和深度，Advisor 无工具、不派工。重投不重复咨询；移交后旧 Leader 不能发起，新 Leader 可读原意见，其他项目不能读。引用已完成文字待办的正例用临时 SQLite 验证。

### 并行验证：额度与长作业

- [共享额度停止](<managed-worker.md#共享额度停止与恢复>)：独立 Web profile 中，临时限流照常重试，明确耗尽会取消同池推理和退避；跨过原退避期限没有新增适配器调用，未映射路由仍可用，重启保留停止。已用模拟飞书 CLI 验证同一故障只向白名单所有者发一次[系统通知](<managed-worker.md#通过飞书接收额度故障通知可选>)，不调用模型。模拟收件后、回执尚未保存时中断独立宿主，重启仍保留原停池和发送记录，显示送达未确认且不重发。改用官方 SDK 后，以模拟回执复验请求只发往配置的所有者；私聊 ID 不匹配时记为送达未确认，重新打开状态库也不重发。另用安装版 `deepseek-account` 适配器接收模拟 HTTP `402`，确认原轮次取消并保存一条 `ACCOUNT_QUOTA` 停池记录，查询不增加推理。真实账户与通知投递未验证。
- [等待外部长作业](<managed-worker.md#等待已提交的外部长作业>)：独立 Web profile 实测同一 systemd 用户服务跨宿主重启，按单调时间运行约 31 分 40 秒；等待不占 Worker，完成后原待办凭现行许可派工一次并可取回成果。另用短时作业验证 Leader 离线时仍可观察完成，重复检查和重启不重放；封池期间只记完成，确认恢复后只接续尚获授权且未暂停的一项。
- [作业观察未知](<managed-worker.md#等待已提交的外部长作业>)：独立 Web profile 验证原调用消失、同名新调用完成时，手工和后台检查仍把原调用记为未知，不消耗许可或派工。另行关联新调用的待办正常交付一次，已确认终态不因该调用随后消失而丢失。
- [首次关联待核实](<managed-worker.md#等待已提交的外部长作业>)：独立 Web profile 实测待核实引用跨重启和移交保留，同名单元完成不会误绑定。交接只显示等待，不复制引用；旧 Leader 和旧候选均不能推进。现任 Leader 修正并核实后，另行派工一次才交付原待办。
- [移交后的作业接续](<managed-worker.md#自动观察和接续可选>)：独立 Web profile 实测同一 Leader Bot 在作业运行期间移交会话。作业完成后，后台只记录状态，不动用旧许可或派工；原会话不能再授权，现任 Leader 另行授权后，原待办才派工并交付一次。
- [后处理中断](<managed-worker.md#自动观察和接续可选>)：独立 Web profile 实测 Worker 已进入本地适配器但未交付时宿主异常退出。重启后外部作业仍为已完成，原后处理记为中断，已用许可不恢复、不重放；关联另一作业的新待办正常交付一次。
- [Watchdog 只读诊断](<managed-worker.md#用-watchdog-查看运行状态>)：独立 Web profile 验证可分别看到暂停、待核对、作业等待、观察未知和额度停止；会话未打开不报失败。查询前后 SQLite 业务记录一致，未新增模型或 systemd 调用。已记录的重启中断和过期宿主读取栅栏另用临时 SQLite 验证。
- [Watchdog 进展疑点](<managed-worker.md#用-watchdog-查看运行状态>)：独立 Web profile 验证同任务同轮次同授权的两次拒绝才提示，暂停时不提示，恢复到新授权后不计旧证据；查询不改业务状态或调用模型。
- [Watchdog 人工受阻状态](<managed-worker.md#用-watchdog-查看运行状态>)：独立 Web profile 验证受阻、未派工、解除与移交后的现任 Leader 分别显示；只读回执不复制受阻说明或增加派工。
- [Watchdog 作业接续状态](<managed-worker.md#用-watchdog-查看运行状态>)：独立 Web profile 用预置记录验证完成观测、暂停与自动许可分别显示；查询不观测外部作业，也不派工。
- [Watchdog 作业暂停先后](<managed-worker.md#用-watchdog-查看运行状态>)：独立 Web profile 用预置记录验证开始早于暂停与预约未开始分别显示；临时 SQLite 验证事务回滚、重启及旧记录先后未确认。
- [Watchdog 项目派工终止证据](<managed-worker.md#用-watchdog-查看运行状态>)：独立 Web profile 验证原生 `TRANSPORT` 终止与派工轮次一致、正常完成无该记录；临时 SQLite 验证尚未结算时两种状态可以同时显示。
- [故障后接替文档执行](<managed-worker.md#确认故障后接替文档执行>)：独立 Web profile 用本地适配器产生真实 DSH 终止事件，验证取消不变更、确认只接替一次且保持暂停；已过 Guard 的旧写入被拒。仅新 Worker 经另行恢复才提交原批准正文一次。
- [文档故障通知](<managed-worker.md#通过飞书接收文档故障通知可选>)：用独立 Web profile 和模拟飞书验证匹配回执记为已送达、错会话回执记为未确认，两者查询和重启均不重复发送，不调用模型或改变任务。

### 记忆与项目档案

- [明确登记的长期偏好](<managed-worker.md#管理已登记的长期偏好>)：独立 Web profile 验证了跨会话纠正、项目限域和遗忘；重启后原会话仍不能用旧版本或同一键恢复正文，历史出处可查，未调用模型。
- [偏好引用](<managed-worker.md#引用一条偏好的指定修订>)：独立 Web profile 验证了跨项目拒绝、纠正或限域后拒绝旧引用，以及遗忘后重启仍只可查历史出处。引用不复制正文，不调用模型。
- [项目事实](<managed-worker.md#从已完成的成果登记项目事实>)：独立 Web profile 验证了原文核对、跨项目拒绝、移交后仅现任 Leader 可修订、重启仍可取回；历史修订只返回出处，归档不发起推理。
- [Bot 经验](<managed-worker.md#保存同一-bot-可复用的经验>)：独立 Web profile 验证了同 Bot 跨项目读取及不同 Bot 隔离。原事实改版后旧经验只可查出处，重启不恢复；没有带入来源项目的摘录或发起推理。
- [自然语言登记长期偏好](<managed-worker.md#用自然语言登记长期偏好>)：独立 Web profile 验证一次性请求、错引文、拒绝确认和重投不保存；明确确认后按原话保存一个新键，可追溯原消息。
- [单项派工使用偏好引用](<managed-worker.md#在一项文字任务中使用偏好引用>)：独立 Web profile 验证偏好只交给该任务的无工具 Worker，重投不派工；来源在入模前更正时 Worker 不调用模型，成果已保存的则只可查出处。
- [自然语言查看偏好与出处](<managed-worker.md#用自然语言查看偏好与出处>)：独立 Web profile 验证全局与项目范围、历史仅见出处、重投不重复；查询只显示原生回执，不调用模型，后续模型也不接收查询正文。
- [自然语言纠正偏好](<managed-worker.md#用自然语言纠正一条偏好>)：独立 Web profile 验证拒绝不写入、同意后按原话保存、重投不重复；另一会话先更正后，旧确认不能覆盖新版本。纠正不调用模型。
- [自然语言限域或遗忘偏好](<managed-worker.md#用自然语言限域或遗忘偏好>)：独立 Web profile 验证拒绝不写入、限域保留原文、遗忘后旧引用失效且同键不能复活；两种操作都不调用模型。
- [移交时自动保存接续记录](<managed-worker.md#查看移交时记录和当前待办>)：独立 Web profile 验证只记录一次，移交后完成的工作只更新当前栏，旧 Leader 和其他项目不能查，重启保留且不派工。
- [单项待办使用项目事实](<managed-worker.md#在一项项目待办中使用当前事实>)：独立 Web profile 验证登记不派工，只有指定 Worker 收到摘录；跨项目拒绝，来源更正在入模前拦住旧摘录，已保存的结果只可查出处。Worker 已进入适配器后才修订所引用的事实时，旧轮次虽正常输出，Studio 仍拒绝保存，重投不派工；引用新修订的独立待办正常交付。移交后只修订另一事实键的对照中，原 Worker 正常结算一次，现任 Leader 可取回正文，原 Leader 只查出处。
- [单项待办引用已交付成果](<managed-worker.md#在一项项目待办中引用已交付成果>)：独立 Web profile 验证绑定不派工，只向指定 Worker 转交摘录；原正文改变但坐标未变时，阻止推理，已完成的派生成果只可查出处。

### 下一步

对照新的 [V1 验收清单](requirements/v1-scope.md#8-v1-验收清单) 与 [现有代码保留与清理边界](requirements/cleanup-and-reuse.md)，以下保留重整前记录的旧局限：

- **真实账户停池待现场核对：** 只在正常使用中出现明确的 `ACCOUNT_QUOTA` 时核对停池和无模型状态查询，不主动耗尽额度。[API Key 路线的 `QUOTA`](<managed-worker.md#共享额度停止与恢复>) 不算这项验收。
- **当前不支持：** 写入动作限于[版本化受管文档](<managed-worker.md#文档写入控制>)，不写普通文件或删除算例结果；外部作业只读观测，不提交、重启或取消，额度恢复也不主动探测。这些边界不算通过了对应动作的验收。
