# 定制进展与下一步

[需求基线](<requirements.md>)不变。第 1 步已通过隔离 Web 宿主验证；第 2 步已接入项目管理权，正在推进跨入口更正和执行接续。首版尚未完成验收。

## 已完成

- **可行性与只读运行时核查。** 原型的渠道、持久化和派工可以复用；动作获批后仍需在实际执行前核对授权，不能只靠 Guard 的初审。核查时，`super-agent` profile 在 DSH `0.2.2-rc.3` 上加载了原型，但因 `repositoryUnset` 未启动业务循环，飞书也未启用。旧路径未改。
- **P0 暂停验证。** 在隔离 DSH 中用真实 Web GUI、工具管线和 SQLite 验证：正常对照写入一次；暂停持久提交后，释放已获批的原动作仍不写入；暂停事务回滚时，GUI 不报「已生效」，同一宿主仍阻止写入。跨重启保护在第 1 步另行验证。
- **受管 Worker 接入和移交验证。** 新增[不依赖 GitHub、默认关闭的实验入口](<managed-worker.md>)。通过原生 Web RPC 验证：移交后释放的旧调用、重启后恢复的同一个旧会话均因 `STALE_EXECUTION` 被拒；只有当前执行轮次的 Worker 成功写入一次。两轮隔离环境均已清理，未改当前 profile。
- **代码整理。** 新增代码注释和预设文字已统一为英文，既有中文本地化保留。两个新模块已补入[架构模块表](<../007-architecture.md#modules>)，类型检查、现有测试和构建均通过。

## 实施顺序

| 顺序 | 工作 | 通过标准 |
| --- | --- | --- |
| **1 · 第一个可用版本（通过隔离 Web 宿主验证）** | 在隔离环境跑通 GUI → Assistant 委派 → 受管 Worker → 原入口取得成果。建立稳定的 Bot、任务和会话标识，先支持一种受管资源。 | 普通文字任务不依赖 GitHub，Assistant 不代做；成果可追溯到 Worker，结束会话后仍可取；暂停和移交仍能阻止旧动作。 |
| **2 · 持续项目与跨入口更正（进行中）** | 增加明确立项和 Leader 当前管理权。GUI 与飞书共用指令登记，处理自然语言更正、重复和迟到的指令、共享文档冲突。 | 换入口更正后接续原任务；旧 Leader 不能再派工，旧 Worker 不能再推进；并发修改不静默覆盖。 |
| **并行 · 额度与长作业** | 验证共享额度池耗尽后底层业务重试确实停止；另选一条现有外部作业路径，验证其跨工作室重启并按条件接续。 | 通知不依赖耗尽的模型；等待释放 Worker 槽位，完成事件不重复接续、不覆盖人工暂停。这两项未通过前，不宣称首版完整验收。 |

### 第 1 步的验证范围

- [普通文字任务](<managed-worker.md#交代文字任务和取回成果>)：DSH `0.2.2-rc.3` 单所有者宿主通过原生 Web RPC 接收消息，用本地固定响应模型验证一次委派、同消息去重、原入口成果与 Worker 来源一致。Worker 会话结束和宿主重启后仍能取回原文，取回不调用模型。未测试线上模型行为或浏览器视觉呈现。
- [受管文档](<managed-worker.md#文档写入控制>)是首个可变资源，只允许替换已登记的正文和版本。普通文字请求不能授予写入权；Assistant 没有业务工具，起草文字的 Worker 没有工具。原型 GitHub 路径保持不变。
- [暂停与重启保护](<managed-worker.md#宿主重启>)：验证过暂停事务回滚后重启仍阻止旧写入；接入 Assistant 后复验暂停、移交和显式恢复，旧 Worker 在移交及重启后均被拒绝，当前轮次只提交一次。

### 第 2 步当前范围

- [项目管理权](<managed-worker.md#建立项目与移交管理权>)：所有者可用原生命令创建项目、复用 Leader Bot 或移交当前管理会话。隔离 Web RPC 验证同一 Bot 的管理轮次 `1 → 2` 后，原先已获准的旧调用也不能登记；旧会话重启后只读，重复输入未新增待办。
- [GUI 文档消息登记](<managed-worker.md#普通消息待核对>)：隔离试用验证原生 Web 收件先保存来源并阻止旧写入，不依赖 Worker 阅读；重投只登记一次，重启后待核对项仍阻止写入。SQLite 登记回滚的对照也验证了不报空箱、重开后保守暂停。登记本身不改变授权范围，所有者在 Web 核对实际效果。
- [飞书私聊登记](<managed-worker.md#飞书私聊登记>)：白名单私聊显式绑定原文档任务，与 GUI 共用待核对列表。独立 profile 中用本地模拟 CLI 验证了拒收不匹配身份和群聊、去重、迟到标记、旧写入阻断及重启后取回。未验证真实飞书送达，不补收断线期间的历史。
- [缩小修改范围并继续原任务](<managed-worker.md#缩小修改范围并继续原任务>)：独立 Web profile 中，从模拟飞书收件，在 GUI 确认只保留部分原批准行；过期确认与已获批的旧写入都被拒，同一 Worker 按新授权只写一次。另用临时 SQLite 核对了窄化事务回滚和暂停保持。
- [共享文档](<managed-worker.md#多个任务修改同一文档>)：独立 Web profile 中，两条已经获批的任务写入竞争同一修订时，只有先提交的一条成功；人工先保存时，旧 Worker 及旧版人工保存也都报冲突。SQLite 保留三个有出处的修订，没有覆盖或多出一次工具提交。
- [Leader 派工和取回](<managed-worker.md#建立项目与移交管理权>)：独立 Web profile 中，旧 Leader 已过 Guard 的派工在移交后仍被拒；现任 Leader 让无工具 Worker 执行同一已登记待办。重投没有第二次执行，重启后仍可读取原文和结果出处。
- [自然语言立项](<managed-worker.md#建立项目与移交管理权>)：独立 Web profile 的原生问答验证了引文不符、拒绝、确认和重投；只有所有者确认才创建项目及独立 Leader，不会派工。
- [自然语言更正](<managed-worker.md#缩小修改范围并继续原任务>)：独立 Web profile 用模拟飞书验证了同任务收件、取消、过期确认及现版生效；建议不调用模型，旧批准不能写入，原 Worker 按新范围只提交一次。
- [飞书文字任务](<managed-worker.md#从飞书发起文字任务并取回>)：独立 Web profile 用本地模拟飞书验证了白名单和前缀约束、一次无工具 Worker 执行；结束会话并重启后，从飞书或 Web 取回同一比较表均不调用模型。未连接真实飞书。
- 下一步关联持续项目的原待办与受管文档任务，验收从跨入口更正到接续和取回成果的完整流程。

### 并行验证：额度与长作业

- [共享额度停止](<managed-worker.md#共享额度停止与恢复>)：独立 Web profile 中，临时限流照常重试，明确耗尽会取消同池推理和退避；跨过原退避期限没有新增适配器调用，未映射路由仍可用，重启保留停止。已用模拟飞书 CLI 验证同一故障只向白名单所有者发一次[系统通知](<managed-worker.md#通过飞书接收额度故障通知可选>)，不调用模型；真实账户与投递未验证。
- [等待外部长作业](<managed-worker.md#等待已提交的外部长作业>)：独立 Web profile 中，同一 systemd 用户服务跨重启继续，等待不占 Worker；后台可在 Leader 离线时观察完成，重复检查和重启不重放。另验证了两项作业在封池时都能记录完成而不派工，确认恢复后只接续尚获授权且未暂停的一项。

首版仍按[需求基线的三条完整流程](<requirements.md#行为验收场景>)验收。
