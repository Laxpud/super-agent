# 定制进展与下一步

[需求基线](<requirements.md>)不变。在独立 DSH Web 宿主中，已走通普通文字委派、持续项目跨入口更正和外部长作业接续三条主流程。结论只覆盖下述已支持的路径，不等于全部需求验收。

## 已完成

- **可行性与只读运行时核查。** 原型的渠道、持久化和派工可以复用；动作获批后仍需在实际执行前核对授权，不能只靠 Guard 的初审。核查时，`super-agent` profile 在 DSH `0.2.2-rc.3` 上加载了原型，但因 `repositoryUnset` 未启动业务循环，飞书也未启用。旧路径未改。
- **P0 暂停验证。** 在隔离 DSH 中用真实 Web GUI、工具管线和 SQLite 验证：正常对照写入一次；暂停持久提交后，释放已获批的原动作仍不写入；暂停事务回滚时，GUI 不报「已生效」，同一宿主仍阻止写入。跨重启保护在第 1 步另行验证。
- **受管 Worker 接入和移交验证。** 新增[不依赖 GitHub、默认关闭的实验入口](<managed-worker.md>)。通过原生 Web RPC 验证：移交后释放的旧调用、重启后恢复的同一个旧会话均因 `STALE_EXECUTION` 被拒；只有当前执行轮次的 Worker 成功写入一次。两轮隔离环境均已清理，未改当前 profile。
- **代码整理。** 新增代码注释和预设文字已统一为英文，既有中文本地化保留。两个新模块已补入[架构模块表](<../007-architecture.md#modules>)，类型检查、现有测试和构建均通过。

## 实施顺序

| 顺序 | 工作 | 通过标准 |
| --- | --- | --- |
| **1 · 第一个可用版本（通过隔离 Web 宿主验证）** | 在隔离环境跑通 GUI → Assistant 委派 → 受管 Worker → 原入口取得成果。建立稳定的 Bot、任务和会话标识，先支持一种受管资源。 | 普通文字任务不依赖 GitHub，Assistant 不代做；成果可追溯到 Worker，结束会话后仍可取；暂停和移交仍能阻止旧动作。 |
| **2 · 持续项目与跨入口更正（文档主流程通过隔离验证）** | 增加明确立项和 Leader 当前管理权。GUI 与飞书共用指令登记，处理自然语言更正、重复和迟到的指令、共享文档冲突。 | 换入口更正后接续原任务；旧 Leader 不能再派工，旧 Worker 不能再推进；并发修改不静默覆盖。 |
| **并行 · 额度与长作业（停止与接续通过隔离验证）** | 验证共享额度池耗尽后底层业务重试确实停止；另选一条现有外部作业路径，验证其跨工作室重启并按条件接续。 | 通知不依赖耗尽的模型；等待释放 Worker 槽位，完成观察不重复接续、不覆盖人工暂停。 |

### 第 1 步的验证范围

- [普通文字任务](<managed-worker.md#交代文字任务和取回成果>)：DSH `0.2.2-rc.3` 单所有者宿主通过原生 Web RPC 接收消息，用本地固定响应模型验证一次委派、同消息去重、原入口成果与 Worker 来源一致。Worker 会话结束和宿主重启后仍能取回原文，取回不调用模型。未测试线上模型行为或浏览器视觉呈现。
- [普通文字 Worker 的组合限制](<managed-worker.md#限定普通文字-worker-的模型组合>)：独立 Web profile 验证 Assistant 委派和 Leader 手动派工只用清单中的深度；清单外不启动 Worker，已核实的深度在实际调用前失效时不进入适配器推理，也不改用其他组合。
- [两角色各自的文字派工默认组合](<managed-worker.md#限定普通文字-worker-的模型组合>)：独立 Web profile 验证双方各用配置的 Worker 组合，不改变发起会话；缺省时沿用本会话，已配置组合失效时不派工或回退。
- [未立项的分项调查与整合](<managed-worker.md#未立项的分项调查与整合>)：独立 Web profile 验证两个无工具 Worker 分别调查、第三个 Worker 根据已保存的原文和出处整合，不创建项目。单项失败时不启动整合；重启后可无模型取回成功的整合结果或失败任务的部分成果。
- [受管文档](<managed-worker.md#文档写入控制>)是首个可变资源，只允许替换已登记的正文和版本。普通文字请求不能授予写入权；Assistant 没有业务工具，起草文字的 Worker 没有工具。原型 GitHub 路径保持不变。
- [暂停与重启保护](<managed-worker.md#宿主重启>)：验证过暂停事务回滚后重启仍阻止旧写入；接入 Assistant 后复验暂停、移交和显式恢复，旧 Worker 在移交及重启后均被拒绝，当前轮次只提交一次。

### 第 2 步当前范围

- [项目管理权](<managed-worker.md#建立项目与移交管理权>)：所有者可用原生命令创建项目、复用 Leader Bot 或移交当前管理会话。隔离 Web RPC 验证同一 Bot 的管理轮次 `1 → 2` 后，原先已获准的旧调用也不能登记；旧会话重启后只读，重复输入未新增待办。
- [GUI 文档消息登记](<managed-worker.md#普通消息待核对>)：隔离试用验证原生 Web 收件先保存来源并阻止旧写入，不依赖 Worker 阅读；重投只登记一次，重启后待核对项仍阻止写入。SQLite 登记回滚的对照也验证了不报空箱、重开后保守暂停。登记本身不改变授权范围，所有者在 Web 核对实际效果。
- [飞书私聊登记](<managed-worker.md#飞书私聊登记>)：白名单私聊显式绑定原文档任务，与 GUI 共用待核对列表。独立 profile 中用本地模拟 CLI 验证了拒收不匹配身份和群聊、去重、迟到标记、旧写入阻断及重启后取回。未验证真实飞书送达，不补收断线期间的历史。
- [缩小修改范围并继续原任务](<managed-worker.md#缩小修改范围并继续原任务>)：独立 Web profile 中，从模拟飞书收件，在 GUI 确认只保留部分原批准行；过期确认与已获批的旧写入都被拒，同一 Worker 按新授权只写一次。另用临时 SQLite 核对了窄化事务回滚和暂停保持。
- [共享文档](<managed-worker.md#多个任务修改同一文档>)：独立 Web profile 中，两条已经获批的任务写入竞争同一修订时，只有先提交的一条成功；人工先保存时，旧 Worker 及旧版人工保存也都报冲突。SQLite 保留三个有出处的修订，没有覆盖或多出一次工具提交。
- [Leader 派工和取回](<managed-worker.md#建立项目与移交管理权>)：独立 Web profile 中，旧 Leader 已过 Guard 的派工在移交后仍被拒；现任 Leader 让无工具 Worker 执行同一已登记待办。重投没有第二次执行，重启后仍可读取原文和结果出处。
- [自然语言立项](<managed-worker.md#建立项目与移交管理权>)：独立 Web profile 的原生问答验证了引文不符、拒绝、确认和重投；只有所有者确认才创建项目及独立 Leader，不会派工。
- [自然语言更正](<managed-worker.md#缩小修改范围并继续原任务>)：独立 Web profile 用模拟飞书验证了同任务收件、取消、过期确认及现版生效；建议不调用模型，旧批准不能写入，原 Worker 按新范围只提交一次。
- [飞书文字任务和同入口更正](<managed-worker.md#从飞书发起文字任务并取回>)：独立 Web profile 用模拟飞书验证了无工具派工和两入口无模型取回。同一私聊可兼顾文档更正；更换重复消息的正文不能改变原路由，迟到的文字任务不会派工。另以临时 SQLite 验证了旧记录兼容、重启及切回旧模式不重放。未连接真实飞书。
- [持续项目文档接续](<managed-worker.md#项目待办关联文档任务>)：独立 Web profile 中，从自然语言确认立项、登记待办到飞书收紧范围，已过 Guard 的旧写入被拒；原 Worker 只提交一次。移交 Leader、共享文档再更新后，Web 仍按原待办取回实际提交的正文和出处，不调用模型。
- [查看已生效的文档范围更正](<managed-worker.md#查看已生效的文档范围更正>)：独立 Web profile 验证待核对不当作决定，生效后可查版本和原消息出处；移交后只有现任 Leader 能查询这段历史，同 Bot 的其他项目不可见。
- [跨入口继续原文档任务](<managed-worker.md#从-web-或飞书继续同一个文档任务>)：独立 Web profile 和模拟飞书验证 Web 多候选时不代选，私聊只接续已绑定的任务；暂停期间拒绝的旧消息重投不启动，原 Worker 按现行授权只写入一次。
- [查证文档写入为何未放行](<managed-worker.md#查看文档写入为何未放行>)：独立 Web profile 验证超范围、已过守卫后暂停和提交故障分别记录、均未改正文；故障排除后的正常对照只写入一次。
- [复核文档范围拒绝](<managed-worker.md#复核明确的文档范围拒绝>)：独立 Web profile 验证按原生调用复核同一版本只记录一次，换证据也不能再复核；临时 SQLite 夹具模拟初审误判，复核发现矛盾但未签发许可或写入。
- [独立 Advisor 咨询](<managed-worker.md#按需咨询-advisor>)：独立 Web profile 验证 Assistant 和现任 Leader 均可发起，实际调用使用指定模型和深度，Advisor 无工具、不派工。重投不重复咨询；移交后旧 Leader 不能发起，新 Leader 可读原意见，其他项目不能读。引用已完成文字待办的正例用临时 SQLite 验证。

### 并行验证：额度与长作业

- [共享额度停止](<managed-worker.md#共享额度停止与恢复>)：独立 Web profile 中，临时限流照常重试，明确耗尽会取消同池推理和退避；跨过原退避期限没有新增适配器调用，未映射路由仍可用，重启保留停止。已用模拟飞书 CLI 验证同一故障只向白名单所有者发一次[系统通知](<managed-worker.md#通过飞书接收额度故障通知可选>)，不调用模型；真实账户与投递未验证。
- [等待外部长作业](<managed-worker.md#等待已提交的外部长作业>)：独立 Web profile 中，同一 systemd 用户服务跨重启继续，等待不占 Worker；后台可在 Leader 离线时观察完成，重复检查和重启不重放。另验证了两项作业在封池时都能记录完成而不派工，确认恢复后只接续尚获授权且未暂停的一项。
- [Watchdog 只读诊断](<managed-worker.md#用-watchdog-查看运行状态>)：独立 Web profile 验证可分别看到暂停、待核对、作业等待和额度停止；会话未打开不报失败。查询前后 SQLite 业务记录一致，未新增模型或 systemd 调用。作业观察未知、已记录的重启中断和过期宿主读取栅栏另用临时 SQLite 验证。
- [Watchdog 进展疑点](<managed-worker.md#用-watchdog-查看运行状态>)：独立 Web profile 验证同任务同轮次同授权的两次拒绝才提示，暂停时不提示，恢复到新授权后不计旧证据；查询不改业务状态或调用模型。
- [故障后接替文档执行](<managed-worker.md#确认故障后接替文档执行>)：独立 Web profile 用本地适配器产生真实 DSH 终止事件，验证取消不变更、确认只接替一次且保持暂停；已过 Guard 的旧写入被拒。仅新 Worker 经另行恢复才提交原批准正文一次。
- [文档故障通知](<managed-worker.md#通过飞书接收文档故障通知可选>)：用独立 Web profile 和模拟飞书验证匹配回执记为已送达、错会话回执记为未确认，两者查询和重启均不重复发送，不调用模型或改变任务。

### 记忆与项目档案

- [明确登记的长期偏好](<managed-worker.md#管理已登记的长期偏好>)：独立 Web profile 验证了跨会话纠正、项目限域和遗忘；重启后原会话仍不能用旧版本或同一键恢复正文，历史出处可查，未调用模型。
- [偏好引用](<managed-worker.md#引用一条偏好的指定修订>)：独立 Web profile 验证了跨项目拒绝、纠正或限域后拒绝旧引用，以及遗忘后重启仍只可查历史出处。引用不复制正文，不调用模型。
- [项目事实](<managed-worker.md#从已完成的成果登记项目事实>)：独立 Web profile 验证了原文核对、跨项目拒绝、移交后仅现任 Leader 可修订、重启仍可取回；历史修订只返回出处，归档不发起推理。
- [Bot 经验](<managed-worker.md#保存同一-bot-可复用的经验>)：独立 Web profile 验证了同 Bot 跨项目读取及不同 Bot 隔离。原事实改版后旧经验只可查出处，重启不恢复；没有带入来源项目的摘录或发起推理。
- [自然语言登记长期偏好](<managed-worker.md#用自然语言登记长期偏好>)：独立 Web profile 验证一次性请求、错引文、拒绝确认和重投不保存；明确确认后按原话保存一个新键，可追溯原消息。
- [单项派工使用偏好引用](<managed-worker.md#在一项文字任务中使用偏好引用>)：独立 Web profile 验证偏好只交给该任务的无工具 Worker，重投不派工；来源在入模前更正时 Worker 不调用模型，成果已保存的则只可查出处。
- [自然语言查看偏好与出处](<managed-worker.md#用自然语言查看偏好与出处>)：独立 Web profile 验证全局与项目范围、历史仅见出处、重投不重复；查询只显示原生回执，不调用模型，后续模型也不接收查询正文。
- [自然语言纠正偏好](<managed-worker.md#用自然语言纠正一条偏好>)：独立 Web profile 验证拒绝不写入、同意后按原话保存、重投不重复；另一会话先更正后，旧确认不能覆盖新版本。纠正不调用模型。
- [自然语言限域或遗忘偏好](<managed-worker.md#用自然语言限域或遗忘偏好>)：独立 Web profile 验证拒绝不写入、限域保留原文、遗忘后旧引用失效且同键不能复活；两种操作都不调用模型。
- [移交时自动保存接续记录](<managed-worker.md#查看移交时记录和当前待办>)：独立 Web profile 验证只记录一次，移交后完成的工作只更新当前栏，旧 Leader 和其他项目不能查，重启保留且不派工。
- [单项待办使用项目事实](<managed-worker.md#在一项项目待办中使用当前事实>)：独立 Web profile 验证登记不派工，只有指定 Worker 收到摘录；跨项目拒绝，来源更正在入模前拦住旧摘录，已保存的结果只可查出处。
- [单项待办引用已交付成果](<managed-worker.md#在一项项目待办中引用已交付成果>)：独立 Web profile 验证绑定不派工，只向指定 Worker 转交摘录；原正文改变但坐标未变时，阻止推理，已完成的派生成果只可查出处。

### 下一步

下一步让所有者按自行排列的组合清单为 Assistant 和 Leader 分别限定派工范围。清单顺序只表示所有者的偏好，不是模型通用能力排名，也不触发自动选型或升级。其他[基线场景](<requirements.md#行为验收场景>)、真实飞书投递和浏览器视觉验收仍待覆盖。
