# 定制进展与下一步

[需求基线](<requirements.md>)不变。已完成运行时核查和受管 Worker 实验；第 1 步正在实施。

## 已完成

- **可行性与只读运行时核查。** 原型的渠道、持久化和派工可以复用；动作获批后仍需在实际执行前核对授权，不能只靠 Guard 的初审。核查时，`super-agent` profile 在 DSH `0.2.2-rc.3` 上加载了原型，但因 `repositoryUnset` 未启动业务循环，飞书也未启用。旧路径未改。
- **P0 暂停验证。** 在隔离 DSH 中用真实 Web GUI、工具管线和 SQLite 验证：正常对照写入一次；暂停持久提交后，释放已获批的原动作仍不写入；暂停事务回滚时，GUI 不报「已生效」，同一宿主仍阻止写入。未确认的暂停不保证跨重启保留。
- **受管 Worker 接入和移交验证。** 新增[不依赖 GitHub、默认关闭的实验入口](<managed-worker.md>)。通过原生 Web RPC 验证：移交后释放的旧调用、重启后恢复的同一个旧会话均因 `STALE_EXECUTION` 被拒；只有当前执行轮次的 Worker 成功写入一次。两轮隔离环境均已清理，未改当前 profile。
- **代码整理。** 新增代码注释和预设文字已统一为英文，既有中文本地化保留。两个新模块已补入[架构模块表](<../007-architecture.md#modules>)，类型检查、现有测试和构建均通过。

## 实施顺序

| 顺序 | 工作 | 通过标准 |
| --- | --- | --- |
| **1 · 第一个可用版本（进行中）** | 在隔离环境跑通 GUI → Assistant 委派 → 受管 Worker → 原入口取得成果。建立稳定的 Bot、任务和会话标识，先支持一种受管资源。 | 普通任务不依赖 GitHub，Assistant 不代做；成果可追溯到 Worker，结束会话后仍可取；暂停和移交仍能阻止旧动作。 |
| **2 · 持续项目与跨入口更正** | 增加明确立项和 Leader 当前管理权。GUI 与飞书共用指令登记，处理自然语言更正、重复和迟到的指令、共享文档冲突。 | 换入口更正后接续原任务；旧 Leader 不能再派工，旧 Worker 不能再推进；并发修改不静默覆盖。 |
| **并行 · 额度与长作业** | 验证共享额度池耗尽后底层业务重试确实停止；另选一条现有外部作业路径，验证其跨工作室重启并按条件接续。 | 通知不依赖耗尽的模型；等待释放 Worker 槽位，完成事件不重复接续、不覆盖人工暂停。这两项未通过前，不宣称首版完整验收。 |

### 第 1 步的实现选择

- 以 DSH `0.2.2-rc.3` Web 单所有者宿主为目标。继续用 SQLite 文档作为首个受管可变资源，只允许按已登记的正文和版本替换，不给 Assistant 或 Worker 开通文件写入、Shell 或业务 API。
- 用专用 Assistant 预设接收 GUI 普通消息，由宿主创建独立的受管 Worker 会话。在首轮投递前保存任务 ID、原会话、负责 Bot、执行会话和轮次。工作请求不是额外写入授权；原型的 GitHub 路径保持不变。
- 将 Worker 的文字成果保存为按任务查找的 SQLite 快照，记录产出会话、执行轮次和来源。成果展示使用原文，不要求 Assistant 重新组织；会话结束或宿主重启后从记录取回。新增快照不等于获准改写受管文档。
- [重启保护](<managed-worker.md#宿主重启>)已实现：隔离 Web RPC 验证暂停事务回滚后旧调用被拒，重启后同一会话仍不能写入，使用当前授权版本显式恢复后仅写一次。

下一步按上述选择接通 Assistant 委派和原入口交付。首版仍按[需求基线的三条完整流程](<requirements.md#行为验收场景>)验收。
